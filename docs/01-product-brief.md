# 01. 제품 기획 브리프

> 상태: 2026-11-24 개정. 첫 초안(2026-11-18, 대화 기반)을 지금까지의 결정(ADR-016~023)과 2026-11-24 팀 회의 합의로 고쳤다. 바뀐 점은 맨 아래 "개정 이력"에 있다.

## 1. 목적
- **관리장은 프로젝트별로 어디까지 진행됐고, 어떤 이슈가 있으며, 다음에 무엇을 해야 하는지를 정기적으로 확인하는 도구다**(2026-11-24 회의).
- 이를 위해 팀원이 따로 기록하지 않아도 Drive·Chat·Gmail·GitHub·AI 작업 도구에 남은 흔적을 읽어 프로젝트 › 태스크 › 작업 내역을 자동으로 정리한다(ADR-016·017).
- 투입 시간(공수)은 후속 과제다. 지금은 작업 내역 건수로 본다(ADR-002).

## 2. 화면이 답해야 할 세 질문
| 질문 | 답하는 방법 |
|---|---|
| 어디까지 진행됐나 | 프로젝트의 상위 단계(리서치·기획·프로토타입·개발·테스트·출시·운영) 진행과 진척률 |
| 다음 단계에 무엇이 필요한가 | 프로젝트별 다음 태스크, 이번 주 예정 업무 |
| 누가 도와야 하나 | 지연·확인 필요, 지원이 필요한 이슈 |

## 3. 관리하는 대상
- **프로젝트 › 태스크 › 작업 내역** 세 단계(ADR-003). 프로젝트는 하나의 목표를 향해 여러 날 이어지는 일의 묶음, 태스크는 끝났다고 말할 수 있는 일, 작업 내역은 실제로 한 일 한 건.
- 프로젝트는 **핵심 프로젝트**와 **AX팀 운영**(채용·이관·교육·주간 일정 등)으로 나눈다(ADR-023).
- 태스크는 **상위 단계**(stage)를 가진다. WBS 번호는 있으면 참고로만 쓴다.
- 업무가 아닌 기록(파일 이동·회의 초대·재공유 등)은 남기지 않는다(ADR-018 §10).
- WBS에 없어도 실제 일이면 태스크·프로젝트로 세운다(ADR-018 §1, ADR-021).

## 4. 사용자
| 사용자 | 하는 일 |
|---|---|
| 본부장·팀 리더 | 주간회의에서 프로젝트별 진행·이슈·다음 단계 확인, 지원이 필요한 곳 판단 |
| 팀원 | 자기 업무가 맞게 잡혔는지 확인, 잘못된 것 정정, 이슈 한 줄 남기기 |
| 관리자 | 사람 초대·권한, 수집 범위·제외 대상 관리 |

## 5. 기능
| 기능 | 상태 |
|---|---|
| 자동 수집(Drive·Chat·Gmail·GitHub·AI 세션·로컬 Git, 하루 4회) | 운영 중 |
| 자동 판별(업무 여부·프로젝트·태스크·완료·지연·확인 필요) | 운영 중 |
| 업무 요약(일·주·월, 사람별), 작업 내역 히트맵 | 운영 중 |
| 프로젝트 영역: 핵심/운영 분리, 별표 고정, 단계 진행, 다음 단계, 이슈, 단계별 태스크 | 2026-11-24 반영 |
| 태스크 드로어(업무 설명·속성·작업 내역·근거), 자료 창 | 운영 중 |
| 로그인·권한(관리자·구성원·보기) | 구현 완료, 배포 대기 |
| 이번 주 예정·지원 필요 이슈 | 배치안에서 결정(데이터 확보 방법 포함) |
| 팀원 계정 연결(사람별 동의) | 설계 |
| 공수(시간) | 후속 |

## 6. 다음 산출물 (2026-11-24 회의)
- **화면 배치안 2~3개**와 각 안에 필요한 데이터·확보 가능 여부(`docs/design/m5-layout-options.html`). 각 안이 세 질문에 답하는지 확인한 뒤 상세 개발.
- 초기 흐름은 "전체 프로젝트 → 이번 주 할 일", 익숙해지면 "이번 주 주요 업무부터"도 검토.

## 7. 제품 원칙
- 자동 판별 우선: 근거가 분명하면 시스템이 반영하고, 애매한 것만 사람이 본다(ADR-016).
- 원문은 저장하지 않는다. 이름·시각·160자 요약만(ADR-017).
- 모든 변경은 delta 한 경로로, 이력과 함께. 사람이 고친 값은 자동으로 덮지 않는다.
- 화면은 라벨만. 설명 문구·시스템 정보·내부 분류 용어를 드러내지 않는다.
- 사람에게 입력을 요구하는 것은 자동으로 알 수 없는 최소한(예: 지원 요청 한 줄)만.
- 리소스 지표를 사람 평가·감시에 쓰지 않는다(ADR-007).

## 8. 성공의 정의
- 주간회의에서 관리장 화면만으로 핵심 프로젝트마다 세 질문(진행·다음 단계·도움 필요)에 답할 수 있다.
- 팀원이 따로 기록하지 않아도 지난주 업무가 프로젝트·태스크별로 정리되어 있다.
- 잘못 잡힌 것을 고칠 경로가 있고, 고친 값이 유지된다.
- 세부 기준은 `docs/05-acceptance-and-metrics.md`.

## 개정 이력
| 날짜 | 바뀐 점 |
|---|---|
| 2026-11-18 | 첫 초안: 리소스(공수) 관리 중심, Project › Workstream › Task › Activity, 사람이 확정 |
| 2026-11-19~23 | 프로젝트 › 태스크 › 작업 내역, 자동 판별 우선(사람 확정 대체), 통합 취합, WBS 무관 판별, 업무 아닌 기록 삭제 |
| 2026-11-24 | 목적을 "진행·이슈·다음 단계 정기 확인"으로 재정의(회의), 핵심/운영 분리, 상위 단계 중심, 배치안 2~3개 후 상세 개발, 공수는 후속 |
