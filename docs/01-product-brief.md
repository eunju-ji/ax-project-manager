# 01. 제품 기획 브리프 (초안)

> 상태: 대화 기반 초기 기획. '권고'는 승인된 정책이 아니다.

## 1. 배경과 목표
- **확정(요청사항)**: AX 프로젝트 관리장을 만들고 Google Workspace(GWS)와 연계해 기록을 자동화하려 한다.
- **확정(요청사항)**: 최종 목적은 **리소스 관리**다. 누가 어떤 일을 했는지, 진행 상황과 투입 현황을 보고자 한다.
- **확정(요청사항)**: Paseo + Claude Code + Codex CLI를 활용해 기획→설계→구현→리뷰→수정 루프를 최대한 자동화하고자 한다.
- **미결정**: AX 팀만 대상인지, 전사 확장 목표인지, GWS의 정확한 조직/관리자 권한이 무엇인지.

## 2. 관리하려는 대상
- Project > Workstream > Task > Activity(증빙 이벤트) **권고**.
- Workstream은 주제/업무영역을 묶는 관리 단위, Task는 완료 산출물과 책임자가 있는 실행 단위, Activity는 문서변경·회의·메시지 같은 증빙 단위.
- Task의 책임 담당자와 참여자는 구분. 여러 사람이 기여할 수 있음.
- 단순 Google Docs 수정 20회가 20개 태스크 또는 20시간 노동을 의미하지 않음.

## 3. 사용자와 의사결정
- **가정**: AX 팀원은 자동 수집된 증빙의 소속 태스크를 확인/수정한다.
- **가정**: 프로젝트 리더는 진행 상태와 리소스 병목을 본다.
- **가정**: 관리자는 팀별 계획 공수와 확인 공수, 향후 가용량을 비교한다.
- **검증 필요**: 팀원·리더·관리자의 실제 의사결정·데이터 열람권한·필요 화면.

## 4. 기능 후보
1. 프로젝트/Workstream/Task 관리(담당자, 기한, 산출물, 완료 기준).
2. 승인된 GWS Drive/Calendar(필요 시 Chat/Gmail) 활동 동기화.
3. 활동 → 프로젝트/태스크 자동 매핑 **후보 제안** + 사용자 확인·수정.
4. 산출물·증빙 링크와 상태 변경 이력.
5. 계획 공수·확인 공수·잔여 예상 공수·가용량 비교.
6. 모호하거나 신뢰도 낮은 자동 매핑의 검토 대기함.
7. 팀/프로젝트별 접근통제, 감사기록, 데이터 삭제 정책.

## 5. 우선 제외 권고
- 개인 AI 채팅 원문 전체 수집, 직원 개인 메일함의 포괄적 수집.
- 편집 횟수, AI 토큰 또는 채팅 시간만으로 투입 공수를 자동 확정.
- 승인 없이 AI가 태스크 완료·공수·평가를 확정하는 기능.
- 첫 버전에서 모든 GWS 서비스와 모든 구성원을 동시 연동.

## 6. MVP 제안
- AX 프로젝트 1~2개, 동의/권한이 확보된 시험 사용자.
- 프로젝트/태스크 계층, Drive·Calendar 우선, 활동-태스크 제안/재배정, 상태/증빙/확인 공수, 간단한 리소스 화면.
- 실제 연결 전 합성 데이터로 End-to-End 시연.

## 7. 중요한 제품 원칙
- '무엇을 했는가'는 Activity evidence, '완료했는가'는 Task acceptance, '얼마나 일했는가'는 별도 Effort record로 분리.
- 시스템이 **추정**한 값과 사람이 **확인**한 값은 항상 구분해 표기.
- AI 추천 결과에는 출처, 시점, 신뢰도, 수정 가능성을 남김.
- 리소스 지표를 사람의 감시/성과 단정에 사용하지 않도록 목적 제한과 사용자 고지 설계.

## 8. 성공의 정의
- 프로젝트 리더가 현재 진행 작업·책임자·블로커를 확인 가능.
- 사용자에게 자동 매핑의 잘못을 수정할 경로가 존재.
- 계획 대비 투입/잔여 공수를 확인 가능하며 데이터 출처와 정확성 제약을 설명 가능.
- 세부 가설과 수치 목표는 `docs/05-acceptance-and-metrics.md` 참고.
