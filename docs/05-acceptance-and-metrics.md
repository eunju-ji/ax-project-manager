# 검증 및 완료 기준

> 2026-11-24 개정: 회의에서 정한 화면 목적(세 질문)을 제품 검증 기준에 추가했다.

## 제품 검증 기준 (2026-11-24 회의)
화면 배치안과 실제 화면은 핵심 프로젝트마다 다음 세 질문에 답할 수 있어야 상세 개발·배포로 넘어간다.
1. **어디까지 진행됐나** — 상위 단계 진행과 진척률이 보인다.
2. **다음 단계에 무엇이 필요한가** — 다음 태스크와 이번 주 예정 업무가 보인다.
3. **누가 도와야 하나** — 지연·확인 필요와 지원이 필요한 이슈가 보인다.
추가로:
- 핵심 프로젝트와 AX팀 운영 항목이 섞이지 않는다.
- WBS 번호를 몰라도 어느 프로젝트의 어떤 단계인지 알 수 있다.
- 프로젝트를 고르면 세부 업무와 관련 파일까지 두 번 이내 이동으로 닿는다.

## Task 완료 기준 (판별)
1. 산출물이 채워졌거나 끝났다는 분명한 근거가 있으면 시스템이 완료로 반영한다(ADR-016·018 §4).
2. 완료일은 결과가 갖춰진 작업 내역의 시각.
3. 근거가 애매하면 완료하지 않고 판단 보류로 남긴다.
4. 상태 변경 이력을 저장하고, 사람이 고친 값은 자동으로 덮지 않는다.

## 파일럿 검증 목표
- 연동 출처 2개 이상(현재 7종) — 달성
- 동일 외부 이벤트 중복 생성 0건
- 사용자가 잘못된 연결을 수정·거절·재연결 가능
- 허가 없는 자료 접근 0건, 수집 제외 대상 유입 0건
- 프로젝트·태스크별 수집 근거 추적 가능
- 업무가 아닌 기록이 작업 내역에 섞이지 않음

자동 판별 정확도 목표는 실제 샘플로 되돌린 비율을 본 뒤 합의한다(ADR-016 §6).

## 에이전트 구현 완료 조건
관련 테스트 통과, 요구사항 검증, critical/high 결함 0개, 보안·권한 변경은 독립 검토 통과, 변경 내용 문서화. 실패 시 최대 3회 수정하고 막히면 보고.
