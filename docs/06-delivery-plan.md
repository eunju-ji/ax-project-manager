# 단계별 추진

> 2026-11-25 개정: 완성일을 12/4(금)로 잡았다. 상세 일정·완료 기준·위험은 `docs/design/m6-milestones.html`.

## 기준이 되는 목적 (회의록 261124)
관리장은 프로젝트별로 **어디까지 진행됐고, 어떤 이슈가 있으며, 다음에 무엇을 해야 하는지 정기적으로(주간회의) 확인**하는 도구다. 배치안과 개발은 세 질문(어디까지 진행됐나 · 다음 단계에 무엇이 필요한가 · 누가 도와야 하나)에 답하는지로 판단하고, 회의에서 정한 순서(배치안 2~3개 → 필요한 데이터·접근 가능 여부 점검 → 상세 개발)를 따른다.

## 마일스톤 (2026-11-25 ~ 12-04, 업무일 8일)
| 마일스톤 | 기간 | 목표 | 완료 기준 |
|---|---|---|---|
| M1 배치안 확정·데이터 점검 | 11/25 ~ 11/27 | 배치안을 세 질문 기준으로 검토·확정, 안별 데이터·접근 가능 여부 점검, 이번 주 예정·지원 요청 확보 규칙 | 확정안 1개 + 데이터 확보표 |

| M3 팀 사용 준비·완성 | 12/2 ~ 12/4 | 팀원 접속(배포·로그인), 판별 보정, 사용 안내, 최종 검토 | 12/4 팀원이 접속해 세 질문 확인 |

## 전체 완성 기준 (12/4)
1. 확정된 배치안의 첫 화면이 핵심 프로젝트마다 세 질문에 답한다.
2. 핵심 프로젝트와 AX팀 운영 항목이 분리되어 있고, 프로젝트를 고르면 세부 업무와 관련 파일로 바로 간다.
3. 이번 주 예정 업무와 지원이 필요한 이슈가 실데이터로 채워진다.
4. 팀원 2~3명이 각자 접속해 볼 수 있다.
5. 다음 주간회의에서 이 화면으로 프로젝트 점검을 진행할 수 있다.

## 12/4 이후
팀원 계정 연결(사람별 동의·수집·팀 단위 중복 제거), Workers 이전, 이번 주 우선 보기·단계 지도, 공수, 프로젝트별 공개 범위, 전사 확장.

## 진행 방식
승인된 태스크 단위로 Build → Test → Review → Fix. 보안·권한 변경은 독립 검토. 작업 브랜치 Push까지 하고 main 병합은 사용자가 한다.
