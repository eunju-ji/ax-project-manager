# ADR-016 자동 판별 우선: 시스템이 판별·수정하고, 정말 어려운 것만 사람이 판단

- 상태: 승인 (2026-11-19) · 출처: 사용자 지시 "팀원이 확인하는 게 아니라, 웬만하면 너가 판별해서 고치는거야. 정말 확인하기 어려운 것만 사람이 판단하고" · legacy P5 "필요한 판단만 사람이 한다"
- 대체: ADR-008의 "자동 제안 + 사람 교정이 기본"과 m1-03 §3의 좁은 자동 허용 목록을 아래로 바꾼다. 수동 생성·교정 경로는 예외 경로로 남는다.

## 결정
1. **프로젝트·태스크 구조는 시스템이 만든다.** 실제 Drive 기록(폴더 구조, 파일 이름·종류, 누가·언제 작업했는지, 파일 간 시간·사람 겹침)에서 LLM이 프로젝트·태스크·작업 내역을 판별해 바로 반영한다. UI 예시 프로젝트는 실제 업무 구조가 아니므로 쓰지 않는다. 사람이 CSV를 채우는 단계는 필수가 아니다(초안 CSV는 점검용 출력으로만 남긴다).
2. **확신이 높으면 자동 반영한다.** 연결(근거 추가·새 작업 내역·새 태스크·새 프로젝트), 이름·업무 유형 지정, 잘못된 연결 수정, 병합·분리도 자동 반영 대상이다. 모든 자동 변경은 근거·확신도·이전 값과 함께 change_log에 남기고 되돌릴 수 있다.
3. **사람에게 보내는 것은 정말 판단하기 어려운 것만**:
   - 근거가 서로 반대로 가리키는 경우(예: 폴더는 A 프로젝트, 파일 이름·참여자는 B 프로젝트)
   - 확신도가 기준 미만인 경우
   - 사람이 이전에 직접 고친 결정을 시스템이 다시 바꾸려는 경우(사람 결정이 우선, 바꾸려면 검토)
   - 실행자를 특정할 수 없는 경우 중 집계에 영향이 큰 경우
4. **사람이 고친 것은 이후 판별의 기준이 된다.** 같은 원본·같은 유형의 다음 판별에 반영한다(m1-03 §4 교정 지속성 유지).
5. **완료 판단 (2026-11-19 사용자 결정: "근거가 분명하면 무조건 너가 알아서 반영")**: ADR-006의 "사람 확정"을 대체한다. 시스템(파일럿에서는 AX-Lead)이 근거가 분명한 태스크를 바로 완료로 반영한다.
   - 분명한 근거: 최종본·배포본·릴리스 공개, 완료·결정 메시지, 결과물이 다음 단계로 넘어간 사실(예: 계획 확정 후 실행 착수), 결과 보고서 작성.
   - 분명하지 않은 것: 파일 수정만 있음, 회의 초대만 있음, "최종"이라는 이름만 있음, 활동이 끊겼을 뿐임. 이런 경우는 진행 중으로 둔다.
   - 완료 반영 시 근거·판단자·시각을 남기고(change_log), 사람이 되돌리면 그 결정이 우선한다(3항).
6. **확신도 기준**: 첫 실수집 데이터로 정한다. 시작값은 보수적으로 두고(자동 반영 후 사람이 되돌린 비율이 높으면 올림), 지표(자동 반영 수, 되돌린 수, 검토로 보낸 수)를 `drive:metrics`로 본다.

## 판별 주체와 데이터 흐름
- 파일럿 단계의 LLM 판별은 **이 Claude Code 세션(AX-Lead)**이 수행한다. 로컬 DB에서 판별에 필요한 최소 정보(폴더 트리, 파일 이름·종류, 시간대별 활동 요약, 사람 후보)만 뽑아 읽고, 결과를 구조화된 JSON으로 돌려주면 로컬 검증기가 확인한 뒤 트랜잭션으로 반영한다. 파일 내용은 쓰지 않는다(ADR-015).
- 이 방식은 회사 메타데이터를 Claude(Anthropic) 서비스로 보낸다. 사용자 지시("너가 판별")에 따른 것이다.
- 서비스에 LLM을 내장해 자동 실행하려면(Claude API 등) 유료 API 승인이 필요하다(AGENTS.md §9). 파일럿 결과를 보고 결정한다.

## 바뀌는 것
- m1-03 §3 자동 허용 목록 → 확신도 기반 자동 반영 + 위 3항 검토 조건
- `drive:structure-draft` → 점검용 출력(필수 아님). `drive:auto-classify`(판별 입력 추출 → 판별 결과 검증·반영)를 추가
- 화면 검토함에는 3항에 해당하는 것만 나온다
