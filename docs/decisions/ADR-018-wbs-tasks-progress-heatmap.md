# ADR-018 WBS를 태스크로 들이기, 진척률·완료·지연 판별, 히트맵 기준

- 상태: 승인 (2026-11-20) · 출처: 사용자 지시 "지금 프로젝트에 있는 wbs같은 건 태스크 기준으로 하고, 그 태스크들로 계산하여 프로젝트는 진척률을 계산하기로 했었잖아", "히트맵은 어떤 기준으로 만들었어? 기준이 모호한 것 같아"
- 관련: ADR-016(자동 판별·자동 완료), ADR-017(통합 취합)

## 1. WBS 행은 태스크로 들인다
- 팀 WBS(현재 `AX팀_11월_업무계획_WBS_202611`)의 **말단 행**(하위 번호가 없는 행, 예: 1.1.1, 3.3, 7)이 태스크 하나다. 상위 행(1, 1.1)은 묶음이며 태스크가 아니다.
- WBS 최상위 번호가 프로젝트 단위다. 기존 프로젝트와 같은 업무면 그 프로젝트에 넣고, 없으면 새 프로젝트를 만든다. 단건 회의·회신 관리(7·8·10)는 `AX팀 운영`에 넣는다.
- 태스크에 남기는 것: WBS 번호(`wbs_code`), 업무명, 담당, 시작일(`start_date`), 종료일(`due_date`), 산출물(요약), 계획 출처(`plan_source: wbs`, `plan_ref`: WBS 파일 source_key).
- 수집 기록(작업 내역)은 맞는 WBS 태스크에 붙인다.
- **(2026-11-23 정정, 사용자 지시)** 업무는 WBS가 있을 수도, 없을 수도 있다. 태스크인지 아닌지는 WBS로 판별하지 않는다(§8 기준). WBS가 없는 태스크도 똑같은 태스크이며, 화면에서 따로 묶거나 "WBS에 없는 업무"·"계획 외" 같은 이름·설명을 붙이지 않는다. WBS 번호가 있으면 번호·묶음을 보여 줄 뿐이다. (`plan_source: activity`는 데이터 출처 표시로만 남는다.)
- 상태: WBS 상태 칸 `완료`는 완료 근거다. `진행중`·`대기`·빈칸은 ADR-016 §5 근거가 있을 때만 완료로 바꾼다. 화면 상태는 저장 상태와 날짜로 정한다: 완료 / 지연·확인 필요(§6) / 진행 중(시작일 지남) / 예정(시작일 전) / 일정 미정(날짜 없음). DB 상태값은 기존 3종을 유지한다.

## 2. 프로젝트 진척률은 프로젝트의 태스크로 계산한다 (2026-11-23 정정)
- **진척률 = 완료 태스크 수 ÷ 태스크 수**(참고 기록 `reference` 제외, WBS 여부 무관).
- **계획 진도 = 종료일이 있는 태스크 중 오늘까지 종료일이 지난 비율**(확인 필요 제외, §6). 종료일 있는 태스크가 없으면 계산·표시하지 않는다. 진척률 < 계획 진도면 "지연".
- 화면에 "계획 없음" 같은 설명 문구는 쓰지 않는다.

## 3. 히트맵은 "사람이 그날 손댄 태스크 수"다
- 이전 기준(하루 작업 내역 수, 색은 기간 최대값 대비)은 소스마다 기록 단위가 달라(Drive 편집 세션, Chat 메시지 1건, 주간 묶음 기록, 회의 1건이 모두 1건) 같은 색이 다른 양을 뜻했다.
- 새 기준: 칸 값 = 그날(KST) 작업 내역이 있는 **(사람, 태스크) 쌍의 수**. 같은 태스크에 기록이 10건이어도 1이다. 담당자 필터 시 그 사람의 태스크 수.
- 색 단계는 고정: 0 / 1 / 2 / 3–4 / 5 이상. 범례에 기준을 적고, 칸 툴팁은 "11월 18일 · 태스크 3개 · 기록 7건".

## 4. 완료는 산출물을 보고 1차로 스스로 판별한다 (2026-11-23 추가, 사용자 지시)
- 출처: "산출물을 보고 완료단계를 스스로 판별할 수 있어야 돼. 그래도 안되면 확인 필요가 뜨는거야. 명확하게 끝난 것들은 내 확인이 없어도 1차적으로 너가 판단하는 거야."
- 판별 순서(AX-Lead, 사람 확인 없이 반영):
  1. WBS 상태 칸 `완료`.
  2. **산출물 확인**: 태스크의 산출물(WBS 산출물 칸·태스크 요약)과 맞는 파일·첨부를 수집 자료에서 찾고, 내용을 읽어 양식만 있는 빈 파일이 아니라 실제 결과가 채워졌는지 본다. 채워져 있으면 완료. 예: 1.1.2 1팀 인터뷰 → `AD본부_AX_인터뷰_결과서_PM1` 정리본이 있으므로 완료.
  3. 최종본·배포본·결과 보고서 공개, 완료·결정 메시지, 다음 단계 착수(ADR-016 §5).
- 위 근거가 없으면 완료로 바꾸지 않는다. 산출물이 있지만 초안 상태이면 진행 중으로 둔다.

## 5. 완료일
- 산출물 근거: 산출물이 결과를 갖춘 시점(초안이 아니라 정리본·결과본이 만들어진 작업 내역 시각).
- 공개·완료 메시지 근거: 그 공개·메시지 시각.
- 다음 단계 착수 근거: 다음 단계 날짜가 아니라 **이 태스크의 마지막 작업 내역 시각**.
- WBS `완료` 표시만 있는 경우: 시트 수정 이력에서 상태가 바뀐 날을 확인할 수 있으면 그 날, 없으면 WBS 종료일.

## 6. 지연과 확인 필요
- **지연**: 종료일이 지났고 완료가 아니며, 이 태스크의 작업 내역이 있다(일이 보이는데 끝나지 않음).
- **확인 필요**: 종료일이 지났고 완료가 아니며, 작업 내역도 완료 근거도 없다(수집 범위에서 일이 보이지 않음). 담당자 확인 대상이며 지연으로 세지 않는다.
- 프로젝트 지연 판정(§2)은 확인 필요 태스크를 분자·분모에서 뺀 값으로 한다. 진척률 표시는 전체 계획 태스크 기준을 유지하고, 확인 필요 건수를 함께 보여 준다.

## 7. 프로젝트 기간
- 가장 이른 기록~가장 늦은 기록(계획 태스크가 있으면 계획 범위). 수집 범위가 짧아 시작일이 늦게 잡히지 않도록 Chat 스페이스·Drive 폴더는 처음 기록까지 거슬러 수집한다(읽기 전용).

## 8. 태스크로 넣을 것과 넣지 않을 것 (2026-11-23 추가, 사용자 지시)
- 출처: "AI 도구 사례 공유 같은 건 태스크라고 볼 수 없어. 좋은 내용을 공유해서 같이 보자는 내용이야. 업무일지도 너가 그 내용을 참고할 수는 있지만 그 자체를 태스크로 넣을 건 아니야."
- **태스크** = 끝낼 수 있는 일. 목표·결과물(또는 완료 상태)이 있고, 누가 해야 하는지 말할 수 있다. 예: 결과서 작성, 대시보드 개발, 이관, 리뷰 회의(결과가 남는 것).
- **태스크가 아닌 것(참고 기록)**:
  - 정보·사례·도구 공유(같이 보자는 내용)
  - 정기 기록: 업무일지·주간보고·개인 체크리스트
  - 계획 문서 갱신 그 자체: WBS·업무계획 수정(내용은 태스크 판별에 쓴다)
  - 회의 일정 조율·초대·채널 운영, 인사·안내
  - 참고 자료 모으기
- 참고 기록은 지우지 않고 `plan_source: "reference"`로 남겨 판별 근거로 쓴다. 화면의 태스크 목록·간트·진척률·히트맵·주간 요약에는 나오지 않는다.
- 판단이 애매하면 "이 일이 끝났다고 말할 수 있는가"로 가른다.
