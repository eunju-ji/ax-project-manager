# ADR-021 프로젝트 판별 기준: WBS가 없어도 일의 흐름으로 프로젝트를 세운다

- 상태: 승인 (2026-11-24, 사용자 지시: "회의에서 나온 '회사 내의 온톨로지 혹은 데이터 구축'을 하고 있어… 이런 프로젝트는 WBS에 없더라도 너가 알아서 프로젝트로 판단해야 돼. 그 프로젝트를 paseo(gpt, claude)를 이용해 구축하고 있어. 나중에는 깃허브와도 연동할 생각인데, 이런 걸 너가 판단해서 프로젝트로 구분하고 표시해야 돼.")
- 관계: ADR-016(구조는 시스템이 만든다)·ADR-018 §1(태스크 여부를 WBS로 가르지 않음)을 프로젝트 단위로 넓힌다.

## 1. 프로젝트란
하나의 목표와 결과물을 향해 여러 날에 걸쳐 이어지는 일의 묶음이다. 계획 문서(WBS)에 있든 없든 같다.

## 2. 프로젝트로 세우는 신호
아래 중 **두 가지 이상**이 같은 주제로 겹치면 프로젝트로 세운다. 하나뿐이면 기존 프로젝트의 태스크인지 먼저 본다.

| 신호 | 예 |
|---|---|
| 전용 작업 공간 | 로컬 작업 폴더, Paseo 워크스페이스, Git 저장소, Drive 폴더, Chat 스페이스 |
| 목표를 적은 문서 | README·PLAN·기획서·회의록에 목적·범위·완료 기준이 있음 |
| 이틀 이상 이어진 작업 | 같은 주제의 커밋·AI 세션·파일 수정이 서로 다른 날에 있음 |
| 회의·지시에서 나온 과제 | 회의록·메일·Chat에서 "~를 구축/추진하자"로 정해진 일 |
| 계획 문서 | WBS·업무계획의 대분류 |

- 도구 이름이 아니라 **목표**로 이름 짓는다. 예: "Paseo 작업"이 아니라 "사내 지식 구축".
- 같은 목표의 작업 공간이 여럿이면(로컬 폴더 + 나중의 GitHub 저장소 + Drive 폴더) 한 프로젝트로 묶는다. 작업 공간과 프로젝트의 대응은 `state.projects_map`에 남겨 다음 판별의 기준으로 쓴다.
- 담당은 작업한 사람(작업 공간의 주인)이다.

## 3. AI 에이전트로 한 일
- Paseo로 띄운 Claude Code·Codex 세션은 이 PC의 세션 기록(`~/.claude/projects`, `~/.codex/sessions`)에 작업 폴더(cwd)와 함께 남는다. 작업 폴더가 곧 작업 공간 신호다.
- 세션은 사람이 시킨 일의 근거다. 수행자는 에이전트가 아니라 지시한 사람이다.
- 아직 GitHub에 올리지 않은 로컬 저장소도 `git log`로 커밋을 읽는다(`state.local_repos`). GitHub에 연결되면 같은 프로젝트에 저장소를 더한다.

## 4. 첫 적용 (2026-11-24)
- **사내 지식 구축**(project_id `kb`): 회사 안의 지식을 AI가 쓰기 좋은 형태(온톨로지·지식 데이터)로 만드는 프로젝트. 회의에서 나온 과제이며 WBS에는 없다. 담당 사용자. 작업 공간: 로컬 `data_lab`(Paseo로 Claude Code·Codex 사용, 로컬 Git).
  - 첫 태스크: OCR·문서 파서 실험실 구축(사내 문서를 지식 데이터로 바꾸기 전 단계로 OCR·PDF 파서를 실제로 돌려 비교·검수하는 도구).
- Moncoti 플랫폼의 "온톨로지 테스트 데이터 구축" 관련 기록은 그 플랫폼의 시험 데이터 일이라 Moncoti에 둔다. 두 프로젝트가 같은 결과물을 쓰게 되면 그때 연결한다.
