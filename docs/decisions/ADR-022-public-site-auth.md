# ADR-022 공개 사이트와 사람별 인증·권한

- 상태: 승인(설계·구현) / 배포 대상은 사용자 결정 대기 (2026-11-24, 사용자 지시: "지금은 내 로컬에서 진행하는 기준으로 만들고 있는데, 이제 공개된 사이트에서 사람마다 인증 권한을 주고 사용할 수 있는 형태로 만들어줘.")
- 관계: ADR-007(보호·접근 감사·목적 제한), ADR-013(트랜잭션 DB가 원본), ADR-014(운영 DB, 예정), ADR-010(승인 게이트: 운영 배포는 G3).

## 1. 로그인
- **Google 로그인(OpenID Connect, Authorization Code + PKCE)**. 팀이 이미 Google Workspace를 쓰므로 별도 비밀번호를 만들지 않는다.
- 회사 도메인 계정만 받는다: ID 토큰의 `hd`가 `ALLOWED_DOMAIN`과 같고 `email_verified`가 참이어야 한다.
- 도메인 계정이어도 **초대된 사람만** 들어온다. 첫 관리자는 환경 변수 `ADMIN_EMAILS`로 정한다.

## 2. 권한
| 역할 | 할 수 있는 일 |
|---|---|
| 관리자(admin) | 사람 초대·역할 변경·비활성화, 모든 화면, 검토 결정, 수집 토큰 관리 |
| 구성원(member) | 팀 화면 보기, 검토 결정·정정 |
| 보기(viewer) | 팀 화면 보기만 |

- 사람 계정은 데이터의 `persons`와 이메일로 연결한다(같은 사람이 화면의 담당자로 나온다).
- 파일럿은 팀 전체 공개(초대된 사람은 팀 데이터를 모두 본다). 프로젝트별 공개 범위는 후속.
- 데모·예시 데이터 모드는 운영 모드에서 끈다.

## 3. 세션·보안
- 서버 저장 세션(SQLite), 쿠키 `__Host-sid`(HttpOnly·Secure·SameSite=Lax), 유휴 12시간·최대 7일, 로그아웃 시 즉시 폐기.
- 상태를 바꾸는 요청은 Origin 확인 + CSRF 토큰.
- 보안 헤더: CSP, HSTS, X-Frame-Options DENY, Referrer-Policy, X-Content-Type-Options.
- 로그인 시도 제한(IP·계정별).
- 접근 감사: 로그인·로그아웃·데이터 조회·권한 변경을 `access_audit`에 남긴다(ADR-007).
- 비밀값(OAuth 클라이언트 시크릿, 세션 키, 수집 토큰)은 환경 변수로만 받고 저장소·로그에 남기지 않는다. 수집 토큰은 해시만 저장한다.

## 4. 수집과의 연결
- 정기 수집은 지금처럼 사용자 PC의 에이전트가 한다(gws-work MCP·로컬 AI 세션이 그 PC에 있다).
- 수집 결과 delta는 **수집 토큰**(Bearer)으로 사이트의 `/api/ingest/delta`에 보내고, 서버가 apply-delta 규칙(검증·제외·이력·재실행)으로 반영한다. 로컬 실행에서는 지금처럼 파일로 반영한다.

## 5. 실행 모드
- `AUTH_MODE=oidc`(운영): 위 규칙 전부.
- `AUTH_MODE=off`: 127.0.0.1에서만 허용(로컬 개발). 다른 주소로 열려 하면 시작하지 않는다.

## 6. 배포 (사용자 결정 대기)
- 컨테이너 이미지(Dockerfile)와 배포 절차서를 준비한다. 실제 배포는 호스팅·도메인·회사 OAuth 클라이언트 등록이 정해진 뒤 G3 승인으로 한다.
- 후보: (A) Google Cloud Run + 영구 디스크 대신 Cloud SQL(ADR-014와 함께 결정), (B) 사내 서버·VM 한 대 + SQLite 볼륨(가장 빠름), (C) 사내 인트라넷 호스팅.
