# ADR-023 관리장 화면 방향: 진행·다음 단계·이슈 중심, 핵심 프로젝트와 팀 운영 분리

- 상태: 승인 (2026-11-24 AX팀 회의 합의, 본부장·팀원 참석)
- 근거: AX팀 미팅 회의록 261124 "1) 프로젝트 관리장"
- 관계: ADR-018(진척률·상태), ADR-021(프로젝트 판별)을 화면 쪽에서 구체화한다. 제품 브리프(`docs/01-product-brief.md`)를 이 방향으로 고쳤다.

## 1. 목적
관리장은 **프로젝트별로 어디까지 진행됐고, 어떤 이슈가 있으며, 다음에 무엇을 해야 하는지**를 정기적으로(주간회의 등) 확인하는 도구다. 화면은 세 질문에 답해야 한다.

| 질문 | 화면에서 답하는 방법 | 데이터 |
|---|---|---|
| 어디까지 진행됐나 | 프로젝트의 상위 단계 진행, 진척률 | 태스크 `stage`, 상태 — 있음 |
| 다음 단계에 무엇이 필요한가 | 프로젝트별 다음 단계(다음 태스크), 이번 주 예정 | WBS 일정·회의 결정 — 일부 있음 |
| 누가 도와야 하나 | 이슈(지연·확인 필요), 지원 요청 | 지연·확인 필요는 있음, **지원 요청은 없음** |

## 2. 결정
1. **핵심 프로젝트와 AX팀 운영 항목을 분리한다.** 채용·이관·교육·주간 일정 같은 운영 항목은 별도 영역(기본 접힘)으로 둔다. 프로젝트에 `kind`(core | ops)를 둔다. 중요한 프로젝트는 별표로 위에 고정할 수 있다.
2. **번호 대신 상위 단계를 먼저 보여 준다.** "3-1" 같은 WBS 번호는 화면에서 숨기고(드로어에만), 태스크에 `stage`(리서치 · 기획 · 프로토타입 · 개발·테스트 · 출시·운영)를 두어 프로젝트 행에 단계 진행을, 펼치면 단계별 태스크를 보여 준다. 단계는 판별 에이전트가 태스크 성격으로 정한다.
3. **프로젝트를 고르면 세부 업무와 관련 파일**을 본다(기존 펼침·드로어·자료 창).
4. **상세 개발 전에 화면 배치안 2~3개**를 만들고, 각 안에 필요한 데이터와 확보 가능 여부를 점검한다(`docs/design/m5-layout-options.html`). 위 1~3은 어느 안에서도 공통이라 먼저 반영했다.

## 3. 데이터 공백과 확보 방법
작업 기록(Drive·GitHub 등)은 **이미 한 일**을 잘 설명하지만, **이번 주 예정 업무**와 **지원이 필요한 이슈**는 기록만으로 알기 어렵다.

| 필요한 것 | 확보 방법(후보) |
|---|---|
| 이번 주 예정 업무 | WBS 일정(시작·종료일이 이번 주인 태스크), 회의록의 "다음 검토 대상·향후 일정" → 예정 태스크로 등록 |
| 지원이 필요한 이슈 | 지연·확인 필요(자동) + 회의록·Chat에서 "도움/결정 필요" 판별 + 담당자가 한 줄로 남기는 이슈(입력이 필요한 유일한 항목, 최소화) |
| 다음 단계 | 미완료 태스크 중 가장 가까운 것(자동), 회의 결정 |

## 4. 첫 화면 흐름
- 초기: **전체 프로젝트를 훑고 → 이번 주 할 일**로 이동.
- 팀이 익숙해지면 **이번 주 주요 업무부터** 보는 흐름도 검토(배치안 B).

## 5. 2026-11-24 반영
- 프로젝트 구분: 핵심 7(관리장, 현업진단, Moncoti, Pi-automate 검토, GBC AdPilot, AX OS, 사내 지식 구축), 운영 4(AX팀 운영, 백엔드 개발자 채용, GWS 공유폴더 이관, AX 교육·Enablement).
- 회의에서 정한 다음 산출물을 예정 태스크로 등록: 관리장 화면 배치안 2~3개, 데이터 벤치마크 랩 WBS(개발실 협의·비교 테스트 포함), Moncoti 설치형 실사용 검증.
