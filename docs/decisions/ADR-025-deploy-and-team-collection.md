# ADR-025 배포와 팀 수집: gws-work만으로, 무료·고정 주소, 하루 1회 이상

- 상태: **제안 — 검증 대기**(2026-11-25). 검증(§5)이 통과하면 승인으로 바꾼다.
- 근거(사용자 조건, 2026-11-25): ① GCP는 gws-work의 것만 쓸 수 있다(우리 OAuth 클라이언트를 따로 만들 수 없음). ② 가능하면 ChatGPT Sites를 쓴다. ③ 아니어도 **무료**로 배포할 수 있어야 한다. ④ **주소가 바뀌면 안 된다.** ⑤ 여러 사람의 데이터를 어떤 방법으로든 **하루 1회 이상** 가져와야 한다.
- 관계: ADR-022(Google 로그인)는 우리 GCP가 있어야 하므로 이 조건에서는 보류한다(코드는 유지, 로그인 방식만 교체 가능하게). ADR-019(팀 단위 판별)를 여기서 실행 구조로 구체화한다.

## 1. 확인한 사실
- **gws-work는 서버형이고 사람마다 자기 Google 연결을 가진다.** 서버가 Google로 사용자를 검증하고(`artiws_whoami`), 사람별 연결 ID·권한 범위·동기화 상태(`artiws_gws_capabilities`, `artiws_sync_status`, 동기화 방식 `desktop-assisted`)를 관리한다. 즉 팀원이 gws-work에 **각자 한 번 연결하면**, gws-work의 GCP로 그 사람의 Drive·Chat·Gmail을 읽기 전용으로 읽을 수 있다. 우리 GCP가 필요 없다.
- ChatGPT Sites와 Cloudflare Workers는 **같은 실행 환경**(Workers + D1)이다. 둘 중 무엇을 고르든 서버를 Workers 방식으로 옮기는 작업은 같아서, 한쪽을 시험하다 다른 쪽으로 바꿔도 작업이 버려지지 않는다.

## 2. 배포 (무료·고정 주소)
| 순위 | 방법 | 주소 | 비용 | 로그인(우리 GCP 없이) |
|---|---|---|---|---|
| **1** | **ChatGPT Sites** | `*.chatgpt.site`(고정) | 사용자 요금제 안(확인 필요) | **Sign in with ChatGPT** + 관리장 초대 목록(초대된 이메일만 입장) |
| 2 | Cloudflare Workers + D1 | `이름.workers.dev`(고정) | 무료 한도 | Cloudflare Access 이메일 인증 코드(무료, 50명까지) 또는 GitHub 로그인 |

- 두 경우 모두 화면·API는 같은 코드(Workers 방식)로 만든다. 지금 Node 서버는 로컬 개발용으로 남긴다.
- 권한(관리자·구성원·보기), 접근 기록, 수집 토큰은 ADR-022에서 만든 규칙을 그대로 옮긴다. 바뀌는 것은 "누구인지 확인하는 방법"뿐이다.

## 3. 팀 수집 (하루 1회 이상)
```
팀원 PC (각자)                         사이트 (Sites 또는 Workers)          사용자 PC (판별)
gws-work에 본인 계정 연결(1회)
매일 정해진 시각 "수집 도우미" 실행  ──▶  /api/inbox (사람별 수집 토큰)  ◀──  하루 4회: 팀 수집함 가져오기
 · 체크포인트 이후 색인만                팀 수집함(사람별 새 기록)              ─ 팀 단위 판별(같은 기록은 하나로)
 · 본문 저장 없음                                                             ─ delta ──▶ /api/ingest/delta
                                        화면(로그인한 팀원)
```
1. **팀원 1회 준비**: gws-work에 본인 Google 계정 연결, 사이트에서 개인 수집 토큰 발급.
2. **수집 도우미(팀원 PC, 하루 1회 이상)**: 작업 스케줄러가 정해진 시각(예: 09:00·13:00)에 실행. gws-work를 본인 계정으로 불러 체크포인트 이후의 색인(파일 이름·작업자·시각, 메시지·메일의 제목·시각·보낸 사람)을 모아 사이트 `/api/inbox`로 보낸다. **판별은 하지 않는다.**
   - 실행 수단은 gws-work가 지원하는 방식에 맞춘다: gws-work에 비대화형 호출(CLI·API 토큰)이 있으면 그것을 쓰고(가장 가볍다), 없으면 팀원 PC의 Claude Code·Codex(또는 Paseo) 예약 실행으로 같은 절차를 돌린다.
3. **판별(사용자 PC, 하루 4회)**: 판별 에이전트가 팀 수집함을 한 번에 가져와 판별한다. 같은 메일·파일·메시지는 고유 ID로 한 건, 수행자는 실제로 한 사람(ADR-019). 결과 delta를 사이트에 올린다.
4. **GitHub**: 공개 저장소는 사용자명만으로(토큰 없음), 비공개는 팀원이 읽기 전용 토큰을 사이트에 등록(암호화 보관). 판별 실행 때 함께 가져온다.
5. **하루 1회를 지키는 장치**
   - 공유 드라이브·팀 스페이스는 사용자 계정의 정기 수집이 이미 읽는다. 팀원 PC가 꺼져도 팀 공용 기록은 빠지지 않는다.
   - 사이트가 사람별 "마지막 수집 시각"을 관리하고, 24시간이 넘으면 관리자 화면에 표시하고 본인에게 알린다.
   - 수집은 체크포인트 방식이라 하루를 건너뛰어도 다음 실행에서 빠진 기간을 이어 받는다.

## 4. 보안·개인정보
- 팀원 데이터는 본인이 연결하고 동의한 범위만. 메일은 업무 메일만 색인(광고·알림 제외), 본문은 판별 때만 읽고 저장하지 않는다.
- 수집 토큰은 사람별, 해시로 저장, 언제든 폐기. 팀원은 자기 수집 기록을 보고 지울 수 있다.
- gws-work 권한은 읽기 액션만 쓴다(지금 규칙과 같음).

## 5. 검증할 것 (승인 전)
| 항목 | 확인 방법 | 안 되면 |
|---|---|---|
| Sites: 요금제 안 무료 여부, API 경로(POST)·비밀값·DB, Sign in with ChatGPT | 작은 시험 사이트 | Workers로(같은 코드) |
| Sites: 주소 고정 | 시험 사이트 재배포 후 주소 확인 | Workers(`workers.dev` 고정) |
| gws-work: 팀원 계정 연결 가능 여부 | 팀원 1명이 연결해 `artiws_whoami` 확인 | 공유 드라이브·팀 스페이스 기록만으로 시작 |
| gws-work: 비대화형(예약) 호출 가능 여부 | gws-work 운영 쪽 확인 또는 시험 | 팀원 PC의 Claude Code·Codex 예약 실행 |
| 수집 도우미 하루 1회 동작 | 팀원 PC 1대에서 이틀 시험 | 실행 시각 늘리기·알림 |

## 6. 일정 (마일스톤 반영)
- M3(12/2~12/4) "팀원 접속"을 이 구조로 한다: 12/2 시험 사이트로 §5 검증 → 12/3 화면·API를 Sites(또는 Workers)에 올리고 초대 로그인 → 12/4 팀원 접속 확인.
- 수집 도우미와 팀 수집함은 12/4 이후 첫 작업(팀원 계정 연결과 함께). 12/4까지는 사용자 PC의 정기 수집(공유 드라이브·팀 스페이스·회의록 포함)으로 화면을 채운다.

## 7. 이식성 원칙 (2026-11-25 추가, 사용자 확인: "나중에 다른 GCP 등으로 옮겨도 괜찮아야")
- 서버를 세 겹으로 나눈다. **핵심**(판별·검증 규칙, 화면 데이터 만들기, 권한 규칙)은 실행 환경과 무관하게 한 벌만 둔다. **연결부**(저장소·로그인·요청 처리)는 플랫폼마다 갈아 끼운다. **화면**은 그대로.
  - 저장소: SQLite(로컬) / D1(Workers·ChatGPT Sites) / Cloud SQL 등(GCP)
  - 로그인: Cloudflare Access / Sign in with ChatGPT / Google OIDC(ADR-022, 구현 완료)
  - 요청 처리: Node http(로컬·컨테이너) / Workers fetch
- 플랫폼 전용 기능은 연결부 밖으로 새지 않게 하고, SQL은 SQLite·D1·PostgreSQL에 공통인 표준 위주로 쓴다.
- 데이터는 delta와 데이터셋 내보내기로 어디서든 꺼내고 넣는다. Node 서버와 Dockerfile은 로컬 개발·컨테이너 배포용으로 유지한다.
- 진행: 1단계 핵심/연결부 분리 → 2단계 Workers 연결부(요청 처리·Access 로그인·토큰 업로드, 로컬 실행 검증) → 3단계 D1 저장소 연결부와 데이터 이전(미룸).
