# ADR-026 화면에서 직접 수정, 간트 표시 규칙

- 상태: 승인(사용자 지시, 2026-11-25). 구현: 브랜치 `feat/ui-1126` 커밋 dccb3dd, 계약 문서 `docs/ui-corrections-api.md`.
- 근거: 팀장 피드백 "잘못 분류된 내용을 화면에서 수정·삭제하면 저장·반영", 사용자 "작업이 잘못 들어가거나 안 들어갔을 때 직접 수정, 확인 필요도 처리 후 다시 고칠 수 있어야".
- 관계: ADR-018(자동/검토 경계), ADR-022(권한), ADR-024(일정 값 정의), ADR-025 §7(핵심/연결부).

## 1. 화면에서 직접 수정
- 대상: 태스크(수정·추가·삭제), 작업 내역(수정·옮기기·추가·삭제), 확인 필요(처리 후 다시 판단).
- 하나의 API `POST /api/correction`. 규칙은 core에 한 벌, 저장은 Node(SQLite·데이터셋 파일)와 Workers 연결부가 각각.
- 권한: 구성원 이상. 보기 권한과 예시 모드에서는 수정 버튼을 숨긴다. 세션·Origin·CSRF는 ADR-022 그대로.
- 사람 수정이 우선: 모든 수정은 history에 수정한 사람(actor_id)과 전후 값을 남긴다. 이후 자동 수집 delta가 같은 필드를 바꾸면 `human_correction_protected`로 거부한다. 삭제는 suppression을 남겨 같은 원본에서 다시 생기지 않게 한다.
- 동시 수정: 엔티티 버전으로 낙관적 잠금(충돌 409). 파일 쓰기는 임시 파일→교체.
- 원문 본문 필드는 수정 경로에서도 받지 않는다. 제목 120자, 설명 200자.

## 2. 간트 표시 규칙
| 요소 | 의미 |
|---|---|
| 태스크 실선 막대 | 계획 기간(시작~마감) |
| 태스크 점선 막대 | 계획 날짜가 없을 때 실제 작업 기간(첫~마지막 작업일) |
| ◆ | 마감일만 있는 태스크의 마감 |
| 점 | 작업 내역이 있는 날(한국 시간 기준) |
| 프로젝트 막대 | 태스크 막대들의 전체 범위, 채움은 진척률 |

- 계획 날짜 출처: WBS 일정(시작·마감), 회의록·요청의 "~까지"(마감, `due_basis`). 그 밖에는 비워 두고 지어내지 않는다.
- 시작일만 있으면 오늘까지 "종료일 미정"으로 그리되, 완료되면 완료일(없으면 마지막 작업일)에서 끝낸다.
- 마감 < 시작이면 막대 대신 "일정 확인 필요".
- 프로젝트 범위의 대체값은 작업 내역 날짜만 쓴다(수집 시각 제외). 모든 태스크가 완료면 오늘까지 늘이지 않는다.
- 진척률에서 합쳐진 태스크 제외(ADR-024).
- 범례 줄은 두지 않고, 막대·점에 마우스를 올리면 뜻을 보여 준다.

## 3. 태스크 상세 표의 대상
선택한 기간(하루·한 주·한 달)과 담당자(전체·특정 사람)에 그 사람이 작업 내역을 남긴 태스크만. 작업 내역 수와 상태 필터 개수도 같은 기준.
