# M2-L 로컬 실행 환경 PoC 설계

> 작성: AX-Lead, 2026-11-19 · 상태: 사용자 승인(로컬 진행) · 게이트 **G0**(외부 서비스·실데이터·유료 API 없음)
> 기준: ADR-002·004·006·010·012, `m1-01`(쓰기 계약·어댑터), `m1-02`(상태 전이), `m1-03`(판별·자동 경계)

## 1. 목적
우리가 정한 저장·판단 규칙이 논리적으로 맞게 동작하는지 PC 안에서 검증한다. 결과는 OD-09(실행 환경·물리 저장소) 비교의 **요구사항 목록**으로 쓴다. Sheets·Apps Script 실제 비교는 G1 승인 후 별도로 한다.

## 2. 구성
```text
[합성 수집 입력] → 수집기(식별·중복 제거) → 판별(가짜 LLM + 규칙) → 쓰기 서비스(Run·CAS)
                                                                   ↓
                                   로컬 표 저장소(JSON 파일, Sheets 제약 흉내)
                                                                   ↓
[브라우저 UI, PoC 모드] ← 로컬 API(127.0.0.1) ← 어댑터(app/src/adapter.js)
```

| 구성 요소 | 내용 |
|---|---|
| 로컬 표 저장소 | 엔터티별 표(행 단위). **행 하나의 조건부 쓰기(버전 비교+적용)는 원자적**으로 제공한다(불변식 1 충족 조건). **여러 행을 묶는 트랜잭션은 제공하지 않는다**(Sheets 한계 흉내). 장애 주입: 지정한 n번째 쓰기 실패, 응답 유실(적용 후 오류 반환) |
| 쓰기 서비스 | m1-01 §4 전체: Run manifest 선기록, ID 선할당, change_id 멱등, payload digest 검사, Review 1회 적용, 재개(최대 3회 후 failed), 미완료 Run 집계 제외 |
| 상태 전이 | m1-02 전이표 T1~T6, 역할 적용 시점 재확인, self_approved, superseded |
| 판별 | m1-03: 자동 허용 목록 4개만 자동, 나머지 Review. 명시적 태스크 ID → Task Link까지만. Suppression(event/source)·해제. 외부 텍스트 지시문 무시 |
| 가짜 LLM | 입력 이벤트별로 미리 정한 제안을 돌려주는 결정적 스텁. 일부러 자동 허용 목록 밖 변경을 요청하는 응답, 지시문 주입 텍스트를 포함한다 |
| 로컬 API | Node 내장 `http`만 사용, `127.0.0.1`에만 바인딩. 뷰 모델 조회, completion 판단 제출 |
| UI PoC 모드 | URL 옵션(예: `?data=local`)일 때만 로컬 API에서 데이터를 읽고 판단을 저장한다. **기본 모드(`data.json`)는 동작·화면이 지금과 완전히 같아야 한다** |

## 3. UI 변경 범위 (PoC 모드에서만)
- 판단 영역에 저장 상태 문구(저장 중 / 저장됨 / 저장 실패 · 다시 시도). ADR-006 요구사항이며 기존 문구·스타일 토큰을 재사용한다. 새 레이아웃·색은 만들지 않는다.
- 새로고침 후 판단 결과 유지(로컬 저장소 기준).
- 기본 모드의 화면 기준선 54장, 탐색 88건은 그대로 통과해야 한다.

## 4. 검증 시나리오 (자동 테스트)
1. 같은 change_id 재시도, 응답 유실 후 재시도 → 1회만 적용
2. 같은 change_id·다른 payload → rejected_payload
3. 같은 버전 동시 요청 2개 → 하나만 적용, 하나는 conflict + Review
4. WorkLog 저장 후 Link 실패 → Run incomplete, 화면 집계 제외 → 재개 → complete, 화면 반영, WorkLog 중복 없음
5. History 기록 실패 → 재개로 보충
6. 복구 3회 실패 → failed
7. 같은 이벤트 재수집 → SourceEvent 1건, 같은 키 다른 digest → 둘 다 보존 + conflict
8. 명시적 TSK ID 커밋 → Task Link 자동, WorkLog 연결은 Review
9. Link 거절(source 범위) → 같은 원본 새 이벤트가 같은 대상으로 제안되지 않음 → 해제 후 다시 제안
10. 억제된 대상을 가리키는 명시적 ID → conflict Review
11. 가짜 LLM의 범위 밖 변경 요청·지시문 주입 → 적용되지 않고 Review
12. 완료 전이 m1-02 §5 시나리오 10개
13. UI PoC 모드(브라우저): 판단 → 저장됨 표시 → 새로고침 후 유지 / 저장 실패 주입 → 실패 표시, 미확인 건수 미확정
14. 수집 실패 주입 → 기존 데이터 불변, Run 실패 기록

## 5. OD-09 비교용 산출물
보고서에 "저장소가 반드시 제공해야 하는 기능" 목록을 남긴다. 예: 행 단위 조건부 쓰기, 쓰기 응답 유실 시 재조회 가능, Run·History 기록 공간, 동시 쓰기 직렬화 방법. 각 항목을 Sheets+Apps Script, 경량 백엔드에서 어떻게 확인할지 G1 PoC 체크리스트로 적는다.

## 6. 제외
실제 Google·GitHub API, OAuth, webhook 수신, 실제 LLM 호출, 배포, 실데이터. 이 PoC의 통과는 운영 저장소 선정을 대신하지 않는다.
