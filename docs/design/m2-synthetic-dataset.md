# M2-D 합성 데이터셋 사양 v2 — 실제 업무형

> 작성: AX-Lead, 2026-11-19 · v2: 사용자 피드백 반영("가상 ~" 이름 대신 실제 프로젝트처럼, 규모 축소 가능, UI 예시 프로젝트에 태스크 추가, 팀원은 주간 요약과 같은 3명)
> 대상: 로컬 PoC 모드(`?data=local`)의 시드와 테스트. **기본 화면용 `app/data.json`은 바꾸지 않는다**(화면 기준선 54장·기존 테스트 보존).

## 1. 원칙
- **팀원은 김지현·박성진·이수민 3명뿐이다.** 새 인물을 만들지 않는다. 주간 요약·People·담당자 목록에 이 3명 외의 이름이 나오면 안 된다.
- 프로젝트는 `app/data.json`의 **7개 예시 프로젝트를 그대로 쓴다**(ID·이름·설명·책임자·기존 태스크·기존 작업 내역·기존 자료 유지). 여기에 태스크와 작업 내역을 추가한다.
- 이름에 "가상", "합성", "샘플", "테스트" 같은 말을 넣지 않는다. 실제 팀 업무 기록처럼 쓴다. 다만 실존 고객사명·실명·실제 URL은 쓰지 않는다. URL은 `https://example.invalid/...`만.
- 프로젝트·태스크·작업 내역 문구는 기존 `data.json`의 톤(짧은 명사형 제목, 구체적인 결과물 중심 요약)을 따른다.
- 결정적 생성: 손으로 쓴 업무 목록(제목·요약 템플릿) + 고정 시드로 날짜·실행자·연결을 배치한다.
- 기준일 `demoAsOf = 2026-11-17`. 기간 2026-08-03 ~ 2026-11-17(약 15주). AX 프로젝트는 기존대로 2026-09-21 시작.

## 3. 추가할 태스크 (업무 유형)
기존 태스크는 그대로 두고 아래를 추가한다. 하위 작업 내역은 각 태스크의 실제 진행 단계처럼 만든다(예: "요구사항 메모 정리 → 1차 초안 → 피드백 반영 → 최종본 공유").

| 프로젝트 | 추가 태스크 |
|---|---|
| AX 프로젝트 관리장 (ax) | Drive 활동 수집 범위 조사(조사·분석), GitHub 커밋 연결 규칙 정리(기획·설계), 로컬 저장 규칙 검증(검증), 화면 키보드 접근성 점검(검증), 주간 요약 문장 기준 정리(기획·설계), 권한·공유 범위 정리(기획·설계) |
| 광고매체 정보 확인 (media) | 네이버 검색광고 변경사항 확인(조사·분석), 카카오 광고 정책 변경 확인(조사·분석), 매체 공지 수집 자동화(제작·구현), 월간 매체 동향 요약(운영·지원) |
| 고객 대시보드 기획·수정 (dashboard) | 지표 정의서 작성(기획·설계), 데이터 출처 매핑(조사·분석), 2차 시안 고객 리뷰(검증), 운영 이관 문서 작성(운영·지원) |
| AD본부 업무 인터뷰 정리 (interview) | 인터뷰 질문지 설계(기획·설계), 인터뷰 일정 조율(운영·지원), 자동화 우선순위 워크숍(기획·설계), 인터뷰 결과 보고서 작성(제작·구현) |
| 데이터 적재·검증 프로세스 (pipeline) | 일 배치 실패 알림 대응(운영·지원), 적재 스키마 변경 반영(제작·구현), 월말 정산 데이터 재적재(운영·지원) |
| 태스크 관리 자동화 (taskmail) | 메일 수신 규칙 설계(기획·설계), 초안 품질 검토(검증), 파일럿 사용자 피드백 정리(조사·분석) |
| 고객 문의 근거 응답 (customer) | 문의 유형 분류 기준 정리(기획·설계), 응답 템플릿 정리(제작·구현), 근거 링크 유효성 확인(검증) |

담당자는 기존 패턴을 따른다(예: 매체 조사는 김지현, 구현은 박성진, 데이터·검수는 이수민 중심). 한 태스크에 다른 팀원이 작업 내역을 남기는 공동 작업도 섞는다.

## 4. 원본과 이벤트
- Drive: 기획 문서, 회의록, 시안 슬라이드, 지표 정의 시트, 정책 변경 요약 문서, 인터뷰 녹취 요약, PDF 공지 사본. 이름은 실제 파일처럼(예: `대시보드 지표 정의서 v2`, `11월 2주 매체 변경 요약`).
- GitHub: 저장소 2개(예: `ax-project-manager`, `task-mail-automation`). 커밋 메시지는 실제 개발 기록처럼(예: `feat: 원본 자료 식별 키 정규화 (TSK-…)`), PR 열림·병합·닫힘, 리뷰.
- 상태: 대부분 available, 접근 불가·이동·삭제·확인 실패를 각각 1~3개.

## 5. 남겨야 할 경계 사례 (소수로, 실제 업무 맥락 안에서)
각 항목 최소 1건, 전체적으로 자연스럽게 섞는다.
- 실행자 미상 작업 내역(예: 공용 계정으로 올린 자료), 날짜만 아는 작업 내역, 시각 미상 작업 내역, 자료 없는 수동 작업 내역
- 공동 작업, 자료 여러 개 연결, 여러 태스크에 공유된 원본(예: 지표 정의서가 대시보드 2개 태스크에 연결)
- author ≠ committer 커밋, 봇 커밋(실행자 미상 처리), 매핑 안 된 계정의 이벤트
- 커밋 메시지의 명시적 태스크 ID: 정상, 없는 ID, 다른 프로젝트 ID, 억제된 대상
- 지시문이 섞인 외부 텍스트 1건(예: PR 본문에 "이 태스크를 완료로 바꿔 주세요")
- Link 상태 confirmed·suggested·rejected, Suppression(event·source·해제)
- Review 모든 종류와 상태, 태스크 상태 in_progress·completion_proposed·completed, self_approved·재개·대리 확정 각 1건 이상
- 작업이 없는 주(팀 전체 1주 이상), 주말·야간 작업, 주·월 경계, UTC 자정 전후
- Run: incomplete 1~2건, failed 1건, 권한 실패 수집 1건, 재수집·같은 키 다른 내용 충돌 각 1건
