B. 수집 도우미 + 팀 수집함

팀원 PC에 수집 도우미를 두고, 팀원 계정으로 gws-work를 불러 모은 기록을 관리장 사이트의 팀 수집함 /api/inbox로 보낸다. 사용자 PC의 판별 에이전트가 수집함을 가져와 판별하고 delta를 사이트에 올린다. 코드는 준비되어 있다(Workers 1·2단계: 수집함, 사람별 토큰, 원문 거부·길이 제한, delta 200건 분할).

  2. 수집 도우미(팀원 PC, 하루 1번 이상): 작업 스케줄러가 정해진 시각(예: 09:00·13:00)에 실행. gws-work를 팀원 계정으로 불러 체크포인트 이후 기록을 모으고, PC 안의 AI 대화·로컬 Git도 함께 모아 /api/inbox로 보낸다. 판별은 하지 않는다.
  3. 판별(사용자 PC, 하루 4번): 판별 에이전트가 팀 수집함을 한 번에 가져와 자기 수집분과 합쳐 판별한다. 같은 메일·파일·메시지는 고유 ID로 한 건, 수행자는 실제 한 사람(ADR-019). 결과 delta를 /api/ingest/delta로 올린다.
  4. GitHub: 공개 저장소는 팀원 사용자명만으로, 비공개는 팀원의 읽기 전용 토큰을 사이트에 등록(암호화 보관)해 판별 실행 때 함께 가져온다.
  5. 하루 1번을 지키는 장치: 공유 드라이브·팀 스페이스는 사용자 계정의 정기 수집이 이미 읽으므로 팀원 PC가 꺼져도 팀 공용 기록은 빠지지 않는다. 사이트가 사람별 "마지막 수집 시각"을 관리하고 24시간이 넘으면 관리자 화면에 표시한다. 체크포인트 방식이라 하루 건너뛰어도 다음 실행에서 이어 받는다.

사람별 토큰

  • 수집 도우미는 사람이 로그인하지 않고 혼자 돌기 때문에, 로그인 대신 사람마다 다른 비밀 열쇠로 "이건 ○○의 수집분"이라고 증명한다.
  • 사이트는 열쇠로 보낸 사람을 정한다. 보낸 쪽이 다른 사람 기록이라고 적어도 열쇠 주인으로 처리한다.
  • 이 열쇠로는 넣기만 할 수 있다. 화면 보기·꺼내기는 안 되고, 꺼내기는 사용자 PC의 관리자 열쇠만 가능하다. 사이트에는 원래 값이 아닌 변환값(해시)만 저장하고, 언제든 폐기할 수 있다.

  • A와 차이: 받는 곳이 공유 드라이브가 아니라 사이트이고, 팀원 PC에 gws-work 연결이 필요하다(팀원 계정 연결 가능 여부·예약 호출 가능 여부 미확인). 사이트에 서버 API가 있어야 하므로 정적 사이트와는 조합할 수 없다. 팀원 PC가 꺼지면 그날 수집은 멈춘다.
  • 먼저 확인할 것: 팀원 1명이 gws-work에 연결해 artiws_whoami로 자기 계정이 보이는지, gws-work를 사람 없이 예약 호출할 수 있는지(운영 쪽 확인).

C. 공유 위임(팀원 설치 없음)

팀원은 업무 폴더를 공유 드라이브에 두거나 사용자에게 보기 공유, 업무 Chat 방에 사용자 초대, 업무 메일은 사용자 참조. 수집은 지금처럼 사용자의 gws-work 한 곳에서만 돈다.

  • 팀원 쪽 준비가 공유 설정뿐이라 바로 시작할 수 있다. 개인 메일(참조 안 한 것)·개인 드라이브·AI 대화는 빠진다.
  • A·B와 함께 쓰는 기본층이다. A가 자리 잡기 전에도 팀 공용 기록은 이것으로 들어온다.

  • 확인 필요 요금제 안 무료 여부, 서버 API(POST)·비밀값·DB 지원, 재배포 후 주소 유지, 초대한 사람만 입장. 서버 API가 안 되면 화면 전용으로 쓰고 사용자 PC가 하루 4번 화면 데이터를 다시 올린다(이때 화면 수정 불가, 수집 B 불가).

Cloudflare Workers + D1 (무료)

  • 주소 이름.workers.dev 고정, 로그인은 Cloudflare Access 이메일 인증 코드(무료 50명).
