# 서비스·데이터 개발의 미해결 질문

이 문서는 반드시 이어받아야 할 질문 목록입니다. 답을 임의로 확정하거나 이 순서대로 구현하라는 계획이 아닙니다.

## Q01. 어떤 기록을 어떻게 수집할 수 있는가?

Drive·Gmail·Chat·GitHub 등에서 실제로 읽을 수 있는 범위는 무엇인가? 특히 ChatGPT·Claude 대화를 사용자가 일일이 옮기지 않고 가져올 방법이 실제로 지원되는가?

전체 대화 자동 접근이 해결됐다는 증거는 없습니다. 지원되는 계정·범위·메타데이터·갱신 방식과 불가능한 부분을 분리해야 합니다. 수동 내보내기를 자동 수집이 완성된 것처럼 제시하지 않습니다.

## Q02. 누가 어떤 권한으로 읽고 쓰는가?

개인별 연결과 팀 공통 연결 중 어떤 방식을 사용하는가? 개인이 읽은 자료의 요약을 팀에 공유할 수 있는 범위는 어디까지인가? 공통 Sheets에 쓰는 실행 계정과 검토 승인 권한은 누구에게 있는가?

## Q03. 기존 태스크·새 태스크·새 작업 내역을 어떻게 구분하는가?

같은 태스크의 추가 근거와 별도 실행 기록을 구분하는 기준은 무엇인가? 이름이 바뀌거나 여러 서비스에서 다르게 불리는 업무를 어떤 근거로 연결하는가? 애매한 연결 후보를 사람이 어떤 정보로 교정하는가?

## Q04. 현재 3단계를 Sheets에 어떻게 저장하는가?

Projects·Tasks·Sources·Reviews·History 구상에서 작업 내역은 어디에 저장하는가? 작업 내역의 ID, 실행자, 시각, 본문, 태스크 관계, 자료 다대다 연결을 어떻게 표현하는가? 기존 공통 데이터가 있다면 ID를 유지하면서 어떻게 맞추는가?

화면의 중첩 JSON은 운영용 저장 스키마 확정본이 아닙니다. 별도 시트를 추가할지 등의 물리 구조는 정해지지 않았습니다.

## Q05. 원본이 없어져도 무엇을 보존하는가?

삭제·이동·권한 변경·일시 접근 실패를 어떻게 확인하는가? 업무 이력을 유지할 최소한의 메타데이터·요약은 무엇인가? 보존 기간과 공유 범위는 무엇인가? 원문을 더 이상 읽을 수 없는 경우 어느 내용을 화면에서 숨겨야 하는가?

## Q06. 갱신은 누가 언제 실행하는가?

이벤트·조회 주기·예약 등 어떤 실행 방식이 실제 연결 환경에서 가능한가? 화면을 닫아도 실행되는가? 사용자가 같은 자료를 반복 입력하지 않게 하려면 어떤 지원이 필요한가? 실행 실패와 오래된 현황을 어떻게 구분하는가?

## Q07. 어느 변경은 자동 처리하고 어느 변경은 검토하는가?

확실한 원본 연결·요약 갱신과 모호한 동일 업무 판단·병합·완료 판단의 경계는 무엇인가? 근거가 충돌하면 어떤 제안을 보여 주는가? 사용자의 교정을 이후 판단에 어떻게 반영하는가?

## Q08. Sheets 변경의 중복·충돌·부분 실패는 어떻게 다루는가?

여러 실행이나 사람이 같은 업무를 고칠 때 덮어쓰기를 어떻게 방지하는가? 작업 내역·자료 연결·변경 이력 중 일부만 저장됐다면 어떻게 감지하는가? 재시도로 같은 업무가 다시 생기지 않게 어떤 식별·검증을 사용하는가?

## Q09. 사람의 판단을 실제 데이터에 어떻게 반영하는가?

현재 UI는 태스크에서 완료·진행 중을 선택할 수 있습니다. 실제 저장 시 승인자·시각·변경 전후·근거를 어디에 남기는가? 저장 실패나 다른 사람의 동시 판단을 어떻게 처리하는가? 판단과 저장 성공을 화면에서 어떻게 구분하는가?

## Q10. 사람별 리소스를 어떤 근거로 보여 주는가?

기록 작성자와 실제 실행자를 어떻게 구분하는가? 실제 작업 시각과 수집 시각이 다르면 어느 주에 집계하는가? 공동 작업·같은 내역의 반복 수집을 어떻게 집계하는가? 현재 건수를 근무 시간·가동률로 오해하지 않게 어떤 설명이 필요한가?

## Q11. 연결 기능을 실제 화면·실행 환경에서 사용할 수 있는가?

대화에서 가능한 조회·쓰기가 화면이나 백그라운드 실행에서도 가능한가? 배포 환경에서 사용자별 권한이 어떻게 적용되는가? 현재 독립 HTML은 서버 연동을 제공하지 않으므로, 목표 실행 환경의 지원 범위를 따로 확인해야 합니다.
