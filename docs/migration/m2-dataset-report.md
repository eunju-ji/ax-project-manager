## 변경 내용

- 유형별 stages 틀을 제거하고 Lead의 변경하지 않은 work-catalogue.json 144개 항목을 제목·요약 그대로 사용한다. 기존 47개 작업 내역은 문구·시각·실행자·자료 연결을 보존한다.
- 기존 태스크에는 준비 작업을 앞에 배치하고 새 태스크에는 카탈로그 순서대로 배치한다. 카탈로그의 함께한 팀원이 있으면 해당 인물이 실행자다.
- doc/sheet/slide/pdf/image는 Drive 원본, commit/pr은 GitHub 이벤트에 연결한다. 원본 제목은 작업 내역 제목이며 생성일은 해당 자료의 첫 사용일이다. none 6건에는 자료를 연결하지 않는다.
- 저장소 2개라는 기존 사양을 유지해 taskmail은 task-mail-automation, 나머지 코드 작업은 ax-project-manager에 둔다. media·pipeline 코드를 이 저장소에 두는 것은 합성 fixture의 임시 분류이며 실제 저장소 소속을 의미하지 않는다. 별도 저장소가 필요하면 사양 §4 조정이 필요하다.
- 분 단위 시각을 분산하고 야간·주말은 소수로 제한했다. UTC 경계는 08:59/09:01 KST 두 건이다.
- datasetVersion=3. 서버 로직은 수정하지 않았다. JSON 해시가 달라지는 기존 시드 메타 규칙으로 백업 후 재시드된다.

## 시각 통계와 남은 간격 예외

| 지표 | 실제 |
|---|---:|
| 정확한 시각이 있는 내역 | 189 |
| 평일 09:00 이상 19:00 미만 KST | 182 / 189 = **96.30%** |
| 주말 또는 22시 이후 | 6 / 189 = **3.17%** |
| 주말 | 2 |
| 날짜만 / 시각 미상 | 각 1 |
| 추가 기록의 동일 HH:MM 최다 반복 | 2 / 142 = **1.41%** |
| 전체의 동일 HH:MM 최다 반복 | 10:00·12:00 각각 23 / 189 = **12.17%** |
| 팀 전체 빈 주 | 2026-08-17~23 |

기존 47건의 10:00·12:00가 각각 23건이므로 전체 동일 분 10% 기준은 보존 조건과 동시에 충족할 수 없다. 테스트는 기존 47건의 정확한 보존을 별도 검사하고 추가 내역의 동일 분 반복을 10% 이하로 검사한다. 사용자 제시의 10%는 예시 기준이며 실제 예외 수치를 위에 공개한다.

업무 기간은 2026-08-03~11-17, AX는 9/21 이후이며 기준일 초과 기록은 없다. 카탈로그 단계 순서 및 기존 기록보다 앞선 준비 단계 배치는 검사 통과다. 기존 태스크 created_at은 기존 화면 보존을 위해 바꾸지 않았으므로 준비 기록이 기존 created_at보다 앞설 수 있다. 이를 엄격한 태스크 기간의 시작으로 해석하면 요구사항 충돌이다.

영업일 간격을 별도 계산한 결과 아래 3구간은 1~6일을 벗어난다. **추가 보정 필요**이며 자동 수정·재검증 3회 제한에 도달해 여기서 중단한다.
