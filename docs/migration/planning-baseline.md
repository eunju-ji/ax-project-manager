# 기획 기준선 (legacy → 3-agent 프로젝트 승계)

> 작성: AX-Lead, 2026-11-19 · 상태: **검토용 초안**(사용자 승인 전)
> 근거 표기: `L00`~`L06` = `docs/legacy-context/00~06_*.md`, `N01`~`N06` = `docs/01~06-*.md`(신규 기획 초안)
> 분류: **[확정]** 과거 문서가 명시적으로 확정했다고 적은 기준 · **[가정]** 설계 방향이지만 검증이 필요한 것 · **[미결정]** 열린 쟁점

## 1. 서비스 목적 [확정]
- 흩어진 업무 기록(요청·대화·문서·코드)을 **프로젝트별 태스크·작업 내역·근거로 연결**해 팀 전체 리소스를 파악한다. 단순 자료 목록·요약 모음이 아니다. (L00 §해결하려는 문제)
- 신규 초안의 "최종 목적은 리소스 관리"(N01 §1)와 일치한다. 다만 "리소스"를 **공수(시간)**로 볼지 **작업 내역 건수·참여**로 볼지는 서로 다르다 → OD-02.

## 2. 승계할 확정 원칙 (L00 §중요하게 확정한 방향)
| # | 원칙 | 비고 |
|---|---|---|
| P1 | 기록을 업무에 연결한다. 메일·문서·커밋은 같은 태스크의 다른 근거일 수 있다 | 원본 1개 ≠ 태스크 1개 (L01) |
| P2 | 사람의 중복 정리 부담을 줄인다. 검증되지 않은 자동 수집을 해결된 것처럼 꾸미지 않는다 | N01 §5 "AI 원문 수집 제외"와 긴장 → OD-06 |
| P3 | 기존 프로젝트·태스크 ID와 연결 관계를 유지한다 | 행 번호·화면 순서를 ID로 쓰지 않음 (L02) |
| P4 | 누가·어떤 기록에서·언제·왜 연결/수정했는지 추적 가능 | N01 §7 "추정값/확인값 구분"과 일치 |
| P5 | 사람은 필요한 판단만 한다(모호한 동일 업무, 충돌, 완료 판단) | N02 D-04와 호환 |
| P6 | 개발→운영이 한 프로젝트에 이어진다. 프로젝트 유형 구분 없음 | L05 §프로젝트와 태스크 |
| P7 | 공통 현황 열람 권한 ≠ 원본 세부 열람 권한 | N01 §4-7, N02 D-07과 일치 |
| P8 | 시스템을 키우지 않는다: **LLM이 판단 · 공통 Sheets가 보관 · 화면이 조회/검토** | 신규 초안 데이터 모델(N04)은 RDB형 → OD-04, OD-09 |

추가 확정 규칙(L01·L02):
- LLM 출력 문장 자체를 사실이나 저장 성공으로 취급하지 않는다. 저장 전에 대상 ID·허용 필드·현재값·권한·승인·중복을 확인한다.
- 실패·권한 부족·불확실성을 기존 확정 정보를 지우는 근거로 쓰지 않는다. "갱신 실패"와 "업무 변경"을 구분한다.
- 같은 원본을 다시 조회한 것은 새 업무가 아니다. **중복 수집 방지(식별)**와 **동일 업무 판단(의미)**은 별개 문제다.
- 메일 작성자 ≠ 실행자일 수 있다. 확인되지 않은 실행자를 추측으로 채우지 않는다. LLM이 요약한 일과 사람이 한 일을 구분한다.
- 원본이 삭제·이동·접근 불가가 돼도 수행한 업무 이력은 사라지지 않는다. 업무 이력 보존과 원문 노출 범위는 분리한다.

## 3. 정보 단위 [확정 용어] / 물리 스키마 [미결정]
| 용어 | 의미 | UI 코드 대응 |
|---|---|---|
| 프로젝트 | 과업 전체, 개발·개선·운영을 계속 연결 | `projects[]` |
| 태스크 | 프로젝트의 구체적 작업. 공통 업무 유형 5종 중 하나로 묶음 | `Task` (`topic`) |
| 작업 내역 | 한 결과/작업물 단위의 실행 기록(누가·언제·무엇) | `Subtask` (`subtasks[]`) |
| 관련 자료 | 업무를 뒷받침하는 원본 문서·파일·저장소·기록 | `files[]` + `sourceId` |

- 공통 업무 유형 **기획·설계 / 조사·분석 / 제작·구현 / 검증 / 운영·지원**은 단계 순서가 아니라 묶음 기준이다 [확정].
- Sheets 5개 논리 구상(Projects/Tasks/Sources/Reviews/History) [가정]. 작업 내역을 어디에 둘지 미정 [미결정 Q04].
- **UI의 중첩 JSON(`data.json`)은 운영 스키마가 아니다** [확정, L04]. 운영 정보(계정 범위·외부 ID·권한·확인 시각·변경 이력)가 아직 없다.

## 4. 구성 요소별 역할 [가정] (L01)
원본 서비스(근거 보관) → 연결 수단(허용 범위 조회) → LLM(연결·갱신 판단) → 팀 공통 데이터 허브(기본: Google Sheets) → 조회·검토 화면(Sites 논의됨, 현재는 독립 TS/CSS 프로토타입).
조회·검토 화면만 가상 데이터 프로토타입으로 구현돼 있고, **실데이터 기반 전체 흐름**(수집·LLM 판단·허브 저장)은 미구현이다. 연결 수단의 읽기/쓰기 지원·실행 환경(Q11)도 검증되지 않았다.

## 5. 실제로 구현된 범위 (L04, 2026-11-19 재검증)
- 정적 프론트엔드 UI: 가상 프로젝트 7 · 태스크 23 · 작업 내역 47 · 자료 68 · 검토 5. 가상 인물 3명(김지현·박성진·이수민), 기준일 `demoAsOf=2026-11-17`.
- 주간 요약(팀/개인, 주 이동), 프로젝트 펼침, 주제별/에피소드 보기, 관련 자료 스크롤 목록, 월 타임라인, Activity·People, 태스크 검토(메모리 상태), 설정·연동 예정 화면(실연결 없음), 6개 테마(테마만 localStorage).
- **새 환경 재검증**: `node --test tests/*.test.cjs` → **26/26 통과**(Node v26.13.0). `typecheck`·`build`는 TypeScript 미설치(node_modules 없음)로 미실행.
- 코드상 외부 네트워크 호출(fetch/XHR) 없음 확인.
- 없는 것: 외부 수집, LLM 판단, Sheets 읽기/쓰기, 로그인·권한, 상태 영속화, 변경 이력, 자동 실행·중복 방지·충돌 처리, 원본 상태 확인, 공수.

## 6. 신규 초안(docs/01~06)과의 비교
> 신규 초안(N01~N06)도 legacy도 대부분 "권고·제안·가정" 수준이다. 아래 "충돌"은 확정 요구사항끼리의 충돌이 아니라 **초안 간 차이**이며, 승인으로 정리할 대상이다.

| 항목 | 신규 초안 | Legacy | 판단 |
|---|---|---|---|
| 계층 | Project>Workstream>Task>Activity (N01, D-03 권고) | 프로젝트>태스크>작업 내역 + 업무 유형 5종 (UI 구현) | **차이** → OD-03 |
| Activity 의미 | 발생 이벤트(문서 변경·회의·메시지), `actor_id`·`happened_at` 보유 | 원본 객체(Source)·작업 내역(WorkLog)·연결을 구분. 이벤트/버전 개념은 명시 없음 | 원본 객체 ≠ 발생 이벤트 ≠ 작업 내역. 셋의 구별 방식 미결정 → OD-04 |
| 리소스 단위 | 계획/확인/잔여 **공수(시간)** (D-02, D-08, MVP·성공 기준·DEV-03에 포함) | **작업 내역 건수**, "시간·가동률 아님" 명시 | **차이, MVP 범위 조정 필요** → OD-02 |
| 기한·진척 | `due_at`, `estimated_hours`, 블로커 확인(N01 §8, N04) | 타임라인 막대는 "예정 기간·진척률이 아님"(표시 의미 규칙), 프로젝트 진척률 미사용 | 직접 충돌은 아님. **표시 의미와 기능 범위 조정 필요** → OD-02 |
| 저장소 | 개념 모델 10개 엔터티 제안 (N04, 저장소 미지정) | Google Sheets 공통 허브 방향(가정), 시스템 최소화 | **물리 저장소 미결정** → OD-04/OD-09 |
| 입력 방식 | MVP "Task CRUD"(DEV-01) | 수동 반복 입력 최소화, LLM이 정리 | 양립 가능(CRUD = 교정 경로). **기본 입력 흐름 확인 필요** → OD-10 |
| 완료 판단 | 담당자 제안 + 책임자 승인 (D-04) | 태스크 판단 영역에서 완료/진행 중 선택, 승인자 미정(Q09) | **호환**, 승인자 정의 필요 → OD-07 |
| 연동 우선 | Drive·Calendar 우선, Chat·Gmail 후속 (N03) | Drive·Gmail·Chat·GitHub·AI 대화 예시(Calendar 배제 아님) | **우선순위 미합의** → OD-05 |
| 접근 감사·목적 제한 | `AccessAudit`, 리소스 지표 감시 사용 금지 고지 (N01 §7, N04) | 공통/원본 권한 분리 | 신규 초안 원칙을 **함께 승계** → OD-08 |
| AI 대화 | 원문 자동 수집 제외, 선택적 요약 (D-06) | 사용자가 옮기지 않고 가져오는 방법을 찾는 것이 질문(Q01) | **긴장** → OD-06 |
| 권한·개인정보 | 최소 권한·감사·보존기간 (D-07) | 공통/원본 권한 분리, 보존 범위 미정(Q02, Q05) | **호환** |
| UI | 언급 없음(신규 개발 전제) | 완성된 프로토타입 존재 | legacy UI 재사용 → `ui-reuse-plan.md` |

## 7. 이번 단계에서 하지 않은 것
- `app/` 코드 변경, 신규 기능 구현, 실데이터(GWS) 접근, 배포, Git commit/push/PR.
- `docs/decisions/`: 새로 **승인된** 결정이 없어 생성하지 않음.
