AX 프로젝트 관리장 — 서비스 명세

지금 만들고 있는 서비스가 무엇을 하고, 누가 어떻게 쓰며, 뒤에서 어떻게 동작하는지 정리한 문서

작성AX-Lead 기준일2026-11-24 버전1.0 단계실데이터 파일럿 운영 · 팀 공개 준비

1. 서비스 개요

한 줄 정의팀원이 따로 기록하지 않아도, 이미 쓰고 있는 도구(Google Drive·Chat·Gmail·GitHub·AI 작업 도구)에 남은 흔적을 읽어 팀의 프로젝트 › 태스크 › 작업 내역을 자동으로 정리해 보여 주는 업무 관리장.

풀려는 문제

업무 기록이 여러 도구에 흩어져 있고, 진척을 보려면 누군가 따로 정리해야 한다. 정리는 늘 늦고, WBS와 실제 작업이 따로 논다.

하는 일

흔적을 모아 같은 업무끼리 묶고, 업무가 아닌 것은 버리고, 완료·지연을 판단해 한 화면에 보여 준다.

다른 점

입력 화면이 없다. 시스템이 먼저 판단하고, 사람은 애매한 것만 본다. 원문은 저장하지 않는다.

핵심 원칙

원칙내용
자동 판별 우선프로젝트·태스크를 세우고, 작업 내역을 붙이고, 완료를 판단하는 것까지 근거가 분명하면 시스템이 바로 반영한다.
업무만 기록무언가를 만들고, 분석·검토·결정하고, 문제를 해결한 기록만 남긴다. 파일 이동·회의 초대·자료 재공유는 남기지 않는다.
WBS와 무관한 판별WBS는 있으면 쓰는 계획 정보다. WBS에 없어도 실제 일이면 태스크·프로젝트로 세운다.
원문 비저장본문은 판단할 때만 읽는다. 저장은 이름·시각·160자 이하 요약뿐이다.
되돌릴 수 있음모든 변경은 한 경로(delta)로만, 이력과 함께 남는다. 사람이 고친 값은 자동으로 덮지 않는다.
라벨만 있는 화면일반 웹서비스처럼 설명 문구 없이 라벨만 둔다. 시스템 정보나 내부 분류 용어를 드러내지 않는다.

사용 장면

월요일 아침, 리더

홈의 "한 주의 업무"를 지난주로 넘겨 프로젝트별로 무슨 일이 있었는지 읽는다. 전체 프로젝트에서 지연·확인 필요 칩이 붙은 태스크를 눌러 드로어에서 근거를 본다.

평소, 팀원

아무것도 입력하지 않는다. 문서를 쓰고, 메일을 보내고, 커밋하고, AI 에이전트에게 일을 시키면 하루 네 번 자동으로 정리된다. 가끔 자기 이름 탭을 눌러 맞게 잡혔는지 본다.

회의에서 새 과제가 생겼을 때

계획 문서에 없어도, 전용 작업 폴더·목표 문서·이틀 이상 이어진 작업이 보이면 시스템이 새 프로젝트로 세운다. 예: "사내 지식 구축".

결과서가 올라왔을 때

시스템이 산출물 파일을 열어 결과가 채워졌는지 보고, 채워졌으면 사람 확인 없이 태스크를 완료로 바꾼다. 완료일은 결과가 갖춰진 날이다.

3. 화면별 기능

한 페이지 구성이다. 위에서 아래로 홈 머리말 → 업무 요약 → 작업 내역 히트맵 → 전체 프로젝트 순서이고, 태스크를 누르면 오른쪽에 드로어가 열린다.

홈 머리말

  • 팀 이름, 참여자 목록(이니셜 아바타 + 영어 이름), 기준일("2026.11.24 기준").
  • 오른쪽 위: 검토 필요 버튼(건수 표시), 설정.
  • 화면 테마 선택: Linear·Notion 등 색상 테마.

업무 요약

홈 첫 번째 영역
  • 기간 단위: 일간 / 주간 / 월간 탭, 이전·다음 이동과 기간 선택.
  • 사람 탭: 전체 또는 사람별로 좁혀 보기.
  • 요약 카드: 작업 내역 건수, 프로젝트 수, 참여 인원, 태스크 수.
  • 프로젝트별 요약: "태스크명: 작업 내역 최대 3개 외 N건" 형식의 문장. 펼치면 작업 내역 목록(제목·담당·시각)이 나오고, 누르면 해당 태스크로 이동.
  • 업무 유형별 작업 내역: 기획·설계 / 조사·분석 / 제작·구현 / 검증 / 운영·지원 5종 분포 막대.
  • 담당자별 작업: 사람마다 작업 내역 수, 태스크 수, 확인 요청 수. 긴 이름은 말줄임.

작업 내역 히트맵

  • 최근 39주(3월부터) 날짜별 칸. 진하기는 그날 작업한 (사람, 태스크) 쌍의 수: 0 / 1 / 2 / 3–4 / 5+.
  • 오늘 이후 칸은 비워 둔다. 범례는 "적음 … 많음".
  • 칸을 누르면 업무 요약이 그날의 일간 요약으로 바뀐다. 사람 탭을 고르면 그 사람 기준으로 바뀐다.

전체 프로젝트 (WBS 간트 표)

  • 검색(프로젝트·태스크 이름), 담당자 필터, "최근 순" 정렬, 모두 펼치기, 월 이동.
  • 프로젝트 행: 이름, 태스크·기록 수, 담당(아바타), 기간, 진척률(완료 ÷ 전체)과 계획 진도, 지연·확인 필요 칩, 목적 한 줄.
  • 묶음 행: WBS의 상위 단계(예: 5.1, 5.2)를 묶음으로 보여 주고 "완료 3/4"처럼 요약.
  • 태스크 행: WBS 번호(있으면), 이름, 담당, 기간("11/4–11/10", 시작일만 있으면 "11/18 ~ 종료일 미정"), 상태 칩.
  • 상태 칩: 완료 · 진행 중 · 지연 · 확인 필요 · 예정 · 일정 미정.
  • 간트 영역: 바는 계획 기간, 파란 점은 실제로 작업한 날, 빨간 세로선은 오늘. 계획보다 일찍·늦게 하면 바와 점이 떨어져 보인다(의도한 표시).
  • WBS가 없는 태스크도 같은 표에 섞여 나온다. 따로 구분하거나 표시하지 않는다.

태스크 드로어

태스크를 누르면 오른쪽에 문서처럼 열림
  • 프로젝트 이름, 태스크 이름, 업무 설명(어떤 일인지 한두 문장).
  • 속성: 상태, 담당, 기간, 산출물.
  • 작업 내역: 날짜별로 묶어 시간·수행자·제목·요약, 그리고 근거 링크(Drive 파일, GitHub 커밋 등).
  • 위·아래 화살표로 이전·다음 태스크, 닫기.
  • 프로젝트를 펼치면 아래에 "관련 자료" 카드(파일·커밋·AI 세션)가 줄지어 나온다.

자료 창

  • 근거 파일을 누르면 그 파일이 들어 있는 폴더의 전체 파일 목록이 열리고, 해당 파일 줄이 2초 동안 연하게 강조된다.
  • 파일 줄을 누르면 그 파일이 바로 열리고, 아래 "Google Drive에서 폴더 열기"를 누르면 폴더가 열린다.
  • GitHub 커밋·PR, claude.ai·ChatGPT 대화처럼 폴더가 없는 근거는 원본 링크만 보여 준다. 링크가 없는 근거(로컬 AI 세션 등)는 이름만 나온다.

검토 필요

  • 시스템이 혼자 정하기 어려웠던 것만 모인다: 완료 확인 요청, 근거가 엇갈리는 연결 등.
  • 구성원 이상이 승인·거절·정정한다. 정정한 값은 이후 자동 판별이 덮지 않는다.

로그인·사용자 관리 구현 완료 · 배포 전

  • "Google 계정으로 로그인" 한 버튼. 회사 도메인 계정이면서 초대된 사람만 들어온다.
  • 관리자 전용 사용자 관리: 목록, 초대(이메일), 역할 변경(관리자·구성원·보기), 비활성화, 화면 담당자와 연결. 자기 자신 강등·마지막 관리자 비활성화는 막는다.
  • 수집 토큰 발급·폐기(사용자 PC의 수집기가 결과를 올릴 때 사용).

내 계정 연결 설계 단계

  • 팀원 각자가 자기 Google(Drive·Chat·Gmail)과 GitHub를 읽기 전용으로 한 번 연결한다. 회사 공동 워크스페이스 없이 여러 사람의 기록을 모으기 위한 화면.
  • 무엇을 연결할지 각자 고르고, 언제든 끊거나 자기 기록을 지울 수 있다.
  • Google은 회사 조직 안의 클라우드 프로젝트로 "내부" 앱을 만들면 재연결 없이 쓸 수 있다. 개인 프로젝트로 만들면 7일마다 재연결이 필요하다(Google 정책).

판별

대상기준
작업 내역만들거나, 분석·검토·결정하거나, 문제를 해결한 기록.
아님: 파일 이동·이름 변경·삭제, 회의 초대·일정 변경, 자료 전달·재공유·링크만 공유, "~하겠다/~해 달라"만 있는 연락, 병합 커밋, 질문만 한 AI 대화, 개인적인 대화.
태스크끝났다고 말할 수 있는 일(목표·결과물·담당이 있음). 같은 목적·결과물로 이어지면 한 태스크로 묶고, 개별 요청·메일 대응·후속 수정은 그 태스크의 작업 내역. 지나치게 잘게 쪼개진 태스크는 합친다.
아님: 정보 공유, 업무일지·주간보고, 계획 문서 갱신 그 자체, 회의 일정 조율, 참고 자료 모으기.
프로젝트하나의 목표를 향해 여러 날 이어지는 일의 묶음. 전용 작업 공간 · 목표를 적은 문서 · 이틀 이상 이어진 작업 · 회의에서 나온 과제 · 계획 문서 중 두 가지 이상이 겹치면 세운다. 도구가 아니라 목표로 이름 짓는다.
수행자실제로 한 사람(파일을 고친 사람, 메일·메시지를 보낸 사람, 커밋한 사람). AI 에이전트에게 시킨 일은 시킨 사람.
업무 유형기획·설계 / 조사·분석 / 제작·구현 / 검증 / 운영·지원 중 하나만.
교차 출처같은 업무가 Drive·메일·Chat·커밋에 따로 남아 있으면 이름·폴더·파일명·참여자·시기·명시적 참조로 대조해 한 태스크에 모은다.

상태와 진척

상태조건
완료산출물 파일을 열어 결과가 채워졌거나, 끝났다는 분명한 근거가 있다. 완료일은 결과가 갖춰진 작업 내역의 시각.
진행 중시작일이 지났고 종료일 전(또는 종료일 없이 작업 중).
지연종료일이 지났고 작업 내역은 있지만 완료 근거가 없다.
확인 필요종료일이 지났는데 작업 내역도 근거도 없다. 사람이 본다.
예정 · 일정 미정시작일 전 / 계획 기간이 없음.
  • 진척률 = 완료 태스크 ÷ 전체 태스크(WBS 여부 무관, 합쳐진 태스크 제외).
  • 계획 진도 = 종료일 있는 태스크 중 종료일이 지난 비율(확인 필요 제외). 진척률이 더 낮으면 뒤처짐.
  • 프로젝트 기간 = 태스크 계획 기간과 작업 내역 중 가장 이른 날 ~ 가장 늦은 날.

사람의 정정

  • 사람이 고친 값(제목·상태·담당 등)은 이력에 남고, 이후 자동 판별이 그 값을 덮지 않는다.
  • 사람이 고친 기록은 자동으로 지워지지 않는다.
  • 특정 프로젝트·사람을 빼 달라는 요청은 기록과 이력 내용까지 지우고(purge), 이후 수집에서도 제외한다.

9. 배포 선택지

지금은 사용자 PC에서만 돈다. 2~3명이 각자 로그인해서 쓰려면 서버를 어딘가에 켜 두어야 한다(앱으로 만들어도 데이터를 내주는 서버는 필요하다).

방법비용PC 꺼져도지금 코드로비고
이 PC + 터널(ngrok·Tailscale 무료 고정 주소)무료안 됨바로가장 빠름. 업무 시간엔 수집 때문에 어차피 켜져 있음. Google이 그 주소를 받아 주는지 시험 필요
이 PC + Cloudflare Tunnel + 내 도메인도메인 연 1만 원대안 됨바로고정 주소가 확실함
Cloudflare Workers + D1무료(수집 CPU가 많으면 월 5달러)됨옮기기 필요항상 켜짐, workers.dev 무료 주소, 예약 실행으로 팀원 계정 수집 가능. 판별은 PC에서
ChatGPT Sites미확인됨옮기기 필요기반이 Workers와 같음. 예약 실행·외부 연동 지원이 문서로 확인되지 않음(공개 베타)
무료 클라우드 VM(Oracle)무료됨바로가입·서버 설정에 손이 감
어느 방법이든 공통으로 필요한 것회사 조직 안의 Google 클라우드 프로젝트(로그인·계정 연결용 "내부" 앱), 고정 주소, 첫 관리자 지정.
