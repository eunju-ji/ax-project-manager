  1. Drive에서 작업‘인터뷰 회의안’ 수정

  3. AI가 작업 유형 판단같은 초안을 다듬은 활동이라 기존 작업에 근거 추가로 판단
  4. 책임자가 완료 확정담당자의 완료 판단과 근거를 확인
  5. 나중에 다시 조회남은 일과 완료된 일, 관련 자료를 확인

AI의 업무 분류와 태스크 완료는 별개다. 담당자가 결과물을 확인하고 책임자가 완료를 확정한다. 주간 화면의 건수는 작업 기록 수이며, 걸린 시간을 뜻하지 않는다.

업무 판별 기준

층위는 리소스 관리에서 내려야 할 결정으로 구분한다. 프로젝트에서는 인력을 어디에 배분할지, 태스크에서는 누가 어떤 결과를 책임질지, 하위태스크에서는 그 결과를 위해 어떤 일을 했는지 본다. 자료가 부족한 층위는 비워 둘 수 있다.

층위구분 기준같은 층위끼리 맞추는 기준
프로젝트하나의 사업·업무 목표 아래 여러 결과물을 묶어 인력과 우선순위를 조정하는 단위독립된 목표와 성과 판단 기준이 있고, 별도로 인력을 배분할 필요가 있는 업무끼리 나눈다. 단일 산출물은 우선 태스크로 검토한다.
태스크한 명의 책임자에게 맡겨 진행·완료를 추적할 수 있는 결과물 단위. 기여자는 여러 명일 수 있다.담당자, 결과물, 완료 기준을 한 문장으로 설명할 수 있어야 한다. 하나의 태스크에 따로 배정하거나 완료할 수 있는 결과가 여러 개라면 나눈다.

현재 제품의 작업 내역		태스크의 결과를 만드는 과정에서 실제로 수행한 의미 있는 작업 묶음. 누가 어떤 기여를 했는지 확인하는 단위다.동일한 중간 결과를 위한 반복 편집은 한 작업에 근거로 묶는다. 준비·실행·검토처럼 기여나 결과가 구분되는 작업은 나눌 수 있다. 저장·열람 같은 개별 이벤트는 근거만 남긴다.

AI가 크기와 경계를 맞추는 순서

  1. 같은 프로젝트의 기존 태스크와 비교한다. AI는 폴더 깊이보다 목표, 결과물, 책임자, 완료 기준을 먼저 본다. ‘온보딩 개선’ 아래에 여러 결과물이 있으면 프로젝트 수준의 묶음으로 보고, ‘질문지 문구 수정’은 독립 배정이 필요 없는 경우 작업 내역으로 본다.
  2. 결과가 독립적으로 완료되는지 본다. ‘인터뷰 설계 및 결과 분석’에서 질문지 확정과 인사이트 보고서 작성이 따로 완료될 수 있다면 두 태스크로 나눈다. 반대로 초안 작성과 여러 차례의 문구 수정이 같은 질문지 확정을 위한 것이면 한 태스크 안에 묶는다.
  3. 작업 내역과 활동 근거를 분리한다. ‘초안 작성’과 ‘이해관계자 검토 반영’은 중간 결과와 기여가 다르면 작업 내역으로 나눌 수 있다. 같은 초안을 저장한 여러 이벤트는 기존 작업의 근거로 붙이고 집계는 늘리지 않는다.
  4. 근거가 닿는 층위까지만 분류한다. 프로젝트만 확실하면 프로젝트를 확인하고 태스크는 미분류로 둔다. 태스크를 찾았어도 기존 작업과의 관계가 불명확하면 태스크 근거로만 보관한다. 빈자리를 채우기 위해 새 업무를 만들거나 작업 건수에 포함하지 않는다.

같은 크기로 정리한 예시

프로젝트태스크 · 독립적으로 완료할 결과하위태스크 · 실제 작업 예시
신규 사용자 온보딩 개선인터뷰 진행안 확정질문지 초안 작성, 검토 의견 반영
사용자 인터뷰 결과 정리인터뷰 진행, 응답을 주제별로 정리
온보딩 개선안 검증테스트 시나리오 작성, 관찰 결과 정리

크기가 비슷하다는 것은 건당 시간이 같다는 뜻이 아니다. 태스크마다 독립적으로 맡기고 완료할 결과가 있고, 작업 내역마다 구분할 만한 기여가 있다는 뜻이다. 이번 기준은 기획안이며, 현재 Drive 파일럿은 폴더·파일명 기반 태스크 연결 제안까지 구현돼 있다.

현재 파일럿의 연결 제안 순서

  1. 업무 목록을 먼저 확정한다. 폴더에서 만든 CSV 초안에 담당자가 포함 여부와 태스크 정보를 입력한다. 목록을 가져오면 그 기준으로 연결 후보를 다시 계산한다.
  2. 기존 태스크 후보를 찾는다. 확정 목록의 폴더 매핑을 우선 본다. 매핑이 없으면 파일명·폴더 경로에 등록된 태스크 이름이나 식별 코드가 있는지 확인한다. 이전에 거절되어 차단된 연결은 후보에서 뺀다.
  3. 후보 수에 따라 검토함에 보낸다. 하나면 연결을 제안한다. 없거나 여러 개면 ‘판단 불가’로 둔다. 팀원이 제안을 확정하거나 다른 태스크로 교정할 수 있다. 작업자를 대조하지 못한 경우도 별도로 표시한다.
  4. 연결과 완료를 따로 처리한다. 연결을 확정하면 태스크에 활동 근거가 붙는다. 태스크 완료는 담당자가 결과물과 완료 기준을 확인한 뒤 프로젝트 책임자가 확정한다.

예외 처리 기준

예외현재 Drive 파일럿추가 설계·확인
폴더가 여러 단계로 중첩됨파일에서 상위로 올라가며 확정 매핑을 찾는다. 파일과 가장 가까운 매핑을 우선하고, 같은 거리에 후보가 여러 개면 자동으로 고르지 않는다.공용 폴더와 참고 자료 폴더를 업무 목록에서 제외할지 담당자가 확인한다.
폴더 매핑과 파일명 단서가 다름수집 시 폴더 매핑이 있으면 그 후보를 사용한다. 파일명·경로의 태스크 코드나 제목은 매핑이 없을 때만 사용한다. 목록 변경 후 재판별은 폴더 매핑만 다시 계산한다.두 단서를 동시에 비교하고, 서로 다른 태스크를 가리키면 충돌 사유를 검토함에 표시하는 방안은 후속 설계다.
후보 없음 또는 복수 후보‘판단 불가’로 검토함에 남긴다. 검토자가 등록된 태스크를 지정하거나 판단 불가로 마무리한다.기존 태스크가 충분히 등록됐는지부터 확인한다. 등록이 충분하고 목적·완료 기준이 다를 때 새 태스크 후보로 올리는 흐름은 제품 설계 범위다.
같은 파일을 여러 번 수정함동일 이벤트가 다시 수집되면 중복 제거한다. 별개의 편집 이벤트는 이력으로 남길 수 있다.같은 결과물을 다듬는 작업은 기존 내역의 근거로 묶고, 별개의 실행과 결과가 확인될 때 새 작업 내역을 제안한다. 편집 횟수로 작업 건수를 늘리는 규칙은 두지 않는다.
사람이 이전에 확정하거나 거절함재판별은 확정 링크와 이미 판단한 검토 건을 보존한다. 차단 이력이 있는 조합은 연결 후보에서 제외한다.거절을 해당 활동에만 적용할지, 같은 파일의 이후 활동에도 적용할지 구분하는 정책은 제품 설계안에 있다.
폴더 이동·접근 권한 상실·작업자 미상수집·가져오기에서 확인한 폴더 정보로 판단한다. 작업자를 확인하지 못하면 미상 검토 건으로 남긴다.이동·권한 상실 후 변경된 경로와 표시 범위를 확인한다. 자료를 볼 수 없게 돼도 이미 남긴 판단과 업무 이력은 보존한다.

같은 업무인지 판단하는 기준

아래는 AI의 업무 판별 기준이다. 세 유형을 AI가 분류하는 것은 목표 흐름이다. 현재 Drive 파일럿 코드는 폴더·파일명 규칙에 따른 연결 제안과 검토 절차를 구현했다.

들어온 활동판단 기준예시
기존 작업의 추가 근거이미 기록한 작업과 같은 결과물을 뒷받침하면 기존 내역에 자료만 추가한다. 작업 건수는 유지한다.‘회의안 초안 작성’에 같은 초안의 수정 기록을 추가
새 작업 내역태스크의 목적 안에서 별도의 실행과 결과가 확인되면 새 내역으로 제안한다.같은 ‘인터뷰 준비’ 태스크에서 회의안 작성 후 질문지 검토를 별도로 기록
새 태스크 후보기존 태스크의 목적이나 완료 기준에 들어가지 않으면 새 태스크 후보로 검토한다.‘인터뷰 준비’와 별개 결과물이 필요한 ‘인터뷰 결과 분석’

제목이 비슷하거나 작업자가 같다는 사실은 후보를 찾는 단서다. 같은 업무인지 확정할 때는 이전 교정, 연결된 자료, 결과물, 완료 기준을 함께 본다.

문제 및 수정

사용 중 생긴 문제왜 생겼나어떻게 바꿨나
저장했다고 나오는데 판단이 반영되지 않음이전에는 판단 결과, 태스크 상태, 변경 기록을 따로 저장했다. 중간에 멈추면 일부만 남았고, 다시 처리해도 실제 반영 여부가 정확히 표시되지 않는 경우가 있었다.관련 기록을 한꺼번에 저장하도록 바꿨다. 중간에 실패하면 함께 되돌리고, 보는 사이 다른 판단이 저장됐으면 기존 결과를 덮어쓰지 않는다.
작업 시간이 자정으로 보이거나 사람별 건수가 어긋남날짜만 아는 기록과 정확한 시각을 아는 기록을 같은 방식으로 처리했다. 작업자가 확인되지 않은 기록도 구별할 필요가 있었다.시각이나 작업자를 모르면 그대로 표시한다. 작업자 미상은 개인별 건수에서 빼고, 같은 작업 기록은 팀 합계에서 한 번만 센다.
Drive에서 가져온 자료를 어느 일에 붙일지 모름파일 이름과 폴더만으로는 담당자나 업무 범위를 확정하기 어렵다. 실제 프로젝트와 태스크 목록도 준비돼 있어야 연결 후보를 찾을 수 있다.폴더에서 업무 목록 초안을 만들고, 사람이 고친 목록을 가져와 연결 후보를 다시 계산하는 기능을 구현했다. 실제 AX-TF 자료에서 후보가 적절한지, 예외가 어떻게 나타나는지 확인이 남아 있다.

작업 기록 · 저장 방식 변경 근거

서비스 구성

  • 가져오기승인된 AX-TF 공유 드라이브에서 파일 정보와 활동을 읽는다. 화면을 열 때마다 Drive를 조회하지 않고, 별도 수집 작업으로 가져온다.
  • 조회 · 로컬 API브라우저는 서버의 조회 API에서 SQLite에 저장된 프로젝트, 주간 현황, 미확정 연결 후보를 받아 표시한다. 검토함은 판단이 필요한 건을 모아 보여준다.
  • 판단 · 업무 서비스서버는 검토 건과 대상 태스크를 확인하고, 근거 연결과 판단 이력을 SQLite에 함께 저장한다. 화면은 서버의 저장 결과를 받는다.

현재 쓸 수 있는 범위 · 예시 화면과 로컬 저장 흐름은 합성 데이터로 확인했다. AX-TF 수집 범위는 승인됐고 수집 기능은 준비됐다. 폴더 초안·CSV 가져오기와 Apps Script 내보내기 자료의 로컬 가져오기 경로도 구현됐다. 회사 환경에서 실제 배포·수집한 결과는 확인되지 않았다.

왜 DB가 필요한가

‘완료 확정’ 한 건은 검토 결과, 태스크 상태, 변경 이력을 함께 바꾼다. 이전 JSON 방식은 이 기록을 따로 쓰다가 중단되면 일부만 남았다. SQLite에서는 관련 변경을 한 트랜잭션으로 처리해 모두 반영하거나 모두 되돌린다. 버전 검사로 동시 판단의 덮어쓰기를 막고, 같은 요청을 다시 보내도 결과가 중복 반영되지 않도록 요청 ID를 기록한다.

  • SQLite · 현재한 PC에서 합성 검증 DB와 파일럿 DB를 별도로 운영한다. 판단·이력 저장, 백업·복원, 판단 기록 내보내기를 로컬에서 검증한다.
  • PostgreSQL · 이관 목표여러 사용자가 서버에서 함께 쓰는 환경을 준비한다. 실제 이관, 동시 사용, 운영 백업은 검증 대상이다.
  • Google Sheets · 공유 사본공유가 필요할 때 DB의 조회 결과를 내보낸다. 업무 상태와 검토 이력은 SQLite 또는 이관 후 PostgreSQL에서 관리한다.
어디에 남나무엇이 남나사용할 때 어떤 차이가 있나
Google Drive문서·파일 원본원문은 Drive에서 본다. 관리장은 파일이나 댓글 본문을 복사해 저장하지 않는다.
SQLite · 업무 데이터파일 이름·경로·활동 정보, 업무와 자료의 연결, 완료 판단과 변경 기록같은 활동을 다시 가져와도 기록이 늘어나지 않고, 팀원이 교정한 결과는 다시 열어도 남는다.
SQLite · 파일럿 DB실제 파일럿 데이터용 공간과 예시 데이터용 공간을 분리예시 기록이 실제 업무 현황에 섞이지 않는다. 사람이 남긴 판단은 이후 옮길 수 있도록 내보내기와 가져오기를 준비했다.
Google Sheets추후 팀 공유용 현황 사본팀이 현황을 보는 용도다. 업무 상태와 판단의 수정은 관리장에서 한다.
