
# AX 프로젝트 관리장 — 최초 실행

당신은 AX 프로젝트 관리장 구축 프로젝트의
Lead Agent다.

CLAUDE.md와 AGENTS.md를 읽고,
현재 프로젝트 문서와 진행 상태를 확인하라.

## 최종 목표
Google Workspace의 업무 활동을 자동으로 수집하고,
프로젝트·태스크·담당자·산출물에 연결하여
리소스 관리를 지원하는 시스템을 구축한다.

## 1. 요구사항 분석
기존 기획 문서를 검토하고 다음을 분석하라.

- 프로젝트 관리 범위
- 프로젝트와 태스크의 적정 분류 체계
- 업무 활동과 태스크의 연결 기준
- 완료 판정 기준
- 담당자별 공수 산정 방식
- 리소스 관리 핵심 지표
- AI를 활용한 업무 기록 자동화 수준
- 사용자가 직접 확인해야 하는 항목

확정 사항, 권고안, 미결정 사항을 구분한다.

## 2. 데이터 연동 분석
다음 시스템의 연동 가능성을 검토하라.

- Google Drive / Docs
- Google Calendar
- Gmail
- Google Chat
- AI 채팅 기록
- GitHub 등 개발 활동

각 항목에 대해 다음을 분석한다.

- 수집 가능한 데이터
- 공식 API 지원 여부
- MCP 활용 가능 여부
- MCP가 없을 때의 연동 대안
- 필요한 인증 및 접근 권한
- 수집 주기와 동기화 방법
- 개인정보 및 보안 위험
- MVP 포함 필요성

확인되지 않은 기술적 가능성을 확정하지 않는다.

## 3. 시스템 설계
다음 항목을 설계하라.

- 사용자별 핵심 시나리오
- 화면 및 기능 구조
- 데이터 모델
- GWS 데이터 수집·정규화 구조
- 활동과 태스크 매핑 방식
- 진행 상태·공수 계산 규칙
- 사용자 확인 및 수정 절차
- 권한·보안·감사 기록 정책

## 4. 독립 검토
주요 기획안을 작성한 후
AX-Reviewer를 최대 1회 호출한다.

검토 범위:
- 요구사항 누락
- 데이터 모델의 구조적 문제
- 연동 기술의 현실성
- 리소스 산정 정확성
- 개인정보·보안 위험
- 불필요하게 복잡한 기능

Reviewer는 파일을 수정하지 않는다.
다른 에이전트를 추가 호출하지 않는다.

## 5. MVP 정의
1차 개발에 반드시 필요한 기능과
후속 개발 기능을 구분한다.

각 기능에 대해:
- 목적
- 입력 데이터
- 처리 로직
- 결과물
- 완료 기준
- 선행 조건
- 기술적 위험

을 정의한다.

## 6. 결과 정리
작성·수정한 문서를 저장하고
tasks/current-state.md를 갱신한다.

사용자에게 다음을 보고한다.

1. 추천하는 최종 기획 방향
2. 주요 설계 선택과 이유
3. MVP 기능 구성
4. 기술 검증 결과
5. 사용자 승인 필요사항
6. 승인 이후 개발 순서

## 7. 실행 제한
- 이번 첫 실행에서는 실제 구현하지 않는다.
- 사용자 승인 없이 실데이터에 접근하지 않는다.
- Builder를 호출하지 않는다.
- Committee를 호출하지 않는다.
- Reviewer는 최대 1회만 호출한다.
- 동일한 분석을 반복하지 않는다.
- 불필요한 추가 질문을 생성하지 않는다.

기획 승인 이후에는
prompts/03-approved-build.md를 기준으로
구현·테스트·리뷰를 시작한다.
